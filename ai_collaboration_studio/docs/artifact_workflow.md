# 会议产物工作流

## 目标

把群聊过程沉淀为可追溯、可编辑、可由用户确认的会议纪要，而不是把模型输出直接当成结论。当前产物包含会议摘要、通用多方案决策板、结论、分歧、待验证事项和待办。

## 多方案决策板

- `decision.options` 最多保存 8 个候选方案；每项有稳定 ID、名称、内容、主要收益、主要风险和独立证据关系。
- `decision.status` 为 `undecided`、`candidate` 或 `deferred`。只有 `candidate` 可以声明“已形成 AI 条件化首选”，且必须至少有两个可比较方案、一个有效 `preferred_option_id`、非空选择理由和经核验的选择证据。这里的首选只是 AI 研究建议，不是用户选择。
- `deferred` 用于如实记录“当前证据不足，暂缓选择”，必须写明原因和经核验的证据；它不会被包装成候选最优。
- 候选方案和首选理由都进入 `artifact_evidence`，并随 `artifact_versions` 冻结。模型生成时全部保持 `unreviewed`，用户必须逐项指定支持、反证或背景用途。
- 该结构适用于项目、体育和交易研究等通用房间；存储产业投委会额外强制至少两个方案和明确 AI 首选。用户随后可以支持同版中的其他候选：必须先确认产物记录，再由用户对精确版本作最终支持、保留或退回；任何动作都不产生订单。

## 轮次绑定与冻结输入合同（正式目标）

存储产业投委会的正式纪要不是“读取房间最近若干消息”的摘要，而是一个由 `round_id` 界定的审计产物：

- `round_id` 必须非空并属于当前房间；关联轮次必须完成正式 12 角色覆盖，其中数据质量官是独立必达角色。
- 生成器必须读取该轮全部成功 AI 消息、消息保存的成员身份版本，以及该轮检查点中的 `round_evidence_manifest_v1`。
- 资料只能使用清单中冻结的确切 ID、版本、正文/快照哈希和截取状态；轮后新增、更新或停用的资料不能进入旧轮纪要。
- 绑定轮次存在有效冻结市场快照时，新建或显式保存产物会由服务端把该轮唯一的 `round_market_snapshot` 精确 revision/SHA 自动加入摘要证据，初始用途与状态固定为 `context + unreviewed`；模型和前端不能提供另一个快照替代它。
- 消息候选只能来自相同 `round_id`；房间中的轮外消息、后续轮消息和“最新 48 条”不得补入正式纪要。
- 数据质量官必须在纪要输入中记录时间截止核验：行情、历史行、报告期、新闻发布时间和材料发布时间不得晚于本轮冻结截止时间。无法证明时按缺失或争议处理。
- 12 个职责未完整成功时，可以生成明确标记为“不完整轮次”的复盘草稿，但不能确认成正式投委会纪要。服务端确认事务会读取关联轮次状态、冻结政策、成功成员集合、同轮 AI 消息及其确切身份版本，重新计算不同成员总数、阶段与职责覆盖；`PAUSED / PARTIAL / CANCELLED` 和身份快照损坏均失败关闭。

当前轮次绑定生成器已强制校验 `round_id`、轮次检查点、冻结共享上下文、行情快照和资料确切版本，并只接收同轮消息作为消息证据；缺少或不匹配时失败关闭。12 角色覆盖由该轮冻结政策和收敛门判定，不绑定轮次的通用草稿不能为正式轮次解锁候选方案。

## 状态与版本

```text
生成或新建 → DRAFT → 用户补充证据并确认 → CONFIRMED
                         ↑                         │
                         └──── 继续编辑生成新草稿 ┘
```

- 每次保存都新增 `artifact_versions` 记录，并通过 `expected_version` 拒绝过期修改。
- 已确认产物再次编辑时会回到 `DRAFT`，清除当前确认标记，但历史版本继续保留。
- 只有用户动作可以把产物标记为 `CONFIRMED`。
- 摘要以外的每个条目都使用稳定 `id`；同一条结论、分歧、待验证或待办在后续版本中修改文本、状态和证据时保留 ID，只有新增条目才生成新 ID。条目身份不能依赖数组下标。
- 产物编辑器中的“版本历史与对比”只读取两个明确版本的冻结快照。标量字段、稳定 ID 条目、纯排序变化和证据关系分别比较；同一来源在不同主张中的引用不会被合并。
- 历史快照以 `artifact_versions.snapshot_json` 为准，不调用当前资料/证据装饰器，也不访问实时行情。列表会显示损坏版本，精确详情对损坏 JSON 或身份/version 不匹配返回 `ARTIFACT_VERSION_CORRUPT`，绝不回退到当前内容。
- 历史版绑定决定使用与写入时相同的规范化哈希合同校验，并区分“该版最新决定”和“现在仍是当前决定”；历史读取本身不写数据库。

## 产物确认与用户最终决定

- `CONFIRMED` 只确认当前版本的会议记录、结构化内容和证据标注，不等同于用户支持 AI 首选或其他候选，也不代表事实已被系统独立证实。
- 用户最终决定是确认之后的独立步骤，只能绑定当前已确认的精确 `artifact_version`。请求中的 `expected_version` 过期、产物仍是草稿或已产生新版本时，服务端失败关闭。
- 决定动作只有 `support`（支持）、`hold`（保留）和 `return`（退回）；三种动作都必须填写理由。`support` 必须显式提交 `selected_option_id`，它可以是同版决策板中任一唯一有效候选，包括与 AI 首选不同的候选。治理适用时还必须精确绑定候选 revision、来源消息、最新消息和治理证明；风险意见 `support / challenge / reject` 都只是复核意见，不自动否决用户选择。`hold` / `return` 必须完全省略所有选择及治理令牌；`return` 表达返回修订要求，产物在用户实际编辑后才进入新的 `DRAFT` 版本。
- 决定以不可变记录追加保存。同一版本再次决定不会改写旧记录，而是让旧记录留在历史中；产物编辑或版本变化后，旧版本决定明确标记为过期，不能被解释为新版本的授权或背书。
- 用户最终决定只改变收敛状态与后续待办，不改变能力合同。支持、保留、退回以及产物确认均固定为无执行能力，不能解锁账户、交易、投注、支付或任何资金动作。

## `decision_package_v2` 与派生谱系

决定包不是另一种自动决策。它以一条用户最终决定为唯一包 ID，把“用户看见并确认的候选产物精确版本”与后续模拟研究资源绑定起来：

```text
已确认候选产物 vN
  ├─ AI 条件化首选 A（只读建议）
  └─ 用户 support 并明确选择 B（decision_package_v2 锚点）
      └─ 模拟组合 v1：implements B
          ├─ 编辑为 v2：revises
          └─ 用户确认精确 v2：confirms
              ├─ 前向观察：tests(PROPOSED)
              │   └─ 用户确认：confirms(PENDING_BASELINE / OPEN)
              │       ├─ 可选补齐基线：revises(OPEN)
              │       └─ 真实到期：records_outcome(RESOLVED)
              └─ 历史 walk-forward：evaluates
```

- 锚点冻结 `decision_version`、`artifact_id + artifact_version`、产物快照哈希、`ai_preferred_option_id`、`selected_option_id`、候选 revision、来源/最新消息、用户所选候选快照与 SHA-256、风险复核适用标记、治理证明哈希和决定记录封印。只有锚点仍是当前决定、封印与事件链完整、动作是 `support` 且用户选择绑定有效时，决定包状态才是 `active` 并允许派生。v2 的 `preferred_option_id` 仅是用户选择的兼容别名；旧 v1 只读保留，不能从 AI 首选反推显式用户选择。
- 当前 `hold` 或 `return` 决定包是 `non_actionable`；被同版更新决定覆盖或因产物产生新版本而失效的包是 `stale`；锚点或链校验失败的包是 `chain_broken`。它们都不能创建新的关联组合、观察或回放。仅对“原 `support` 仍完整、且观察在过期前已合法绑定”的同一观察，`stale` 包允许续记确认、基线补齐与真实到期事件；这是完成既有审计生命周期，不是恢复派生权限。`chain_broken` 没有该例外。
- 从当前完整 `support` 新建关联模拟组合时必须填写推导说明，并追加 `implements`；组合保存新版本追加 `revises`；风险门通过后由用户确认精确版本才追加 `confirms`。关联不会把候选文字自动翻译成权重，具体纸面方向、预算、失效条件仍由用户审查。
- 讨论轮中由 AI 生成的原始 `PROPOSED` 观察，可以在精确组合确认后由用户显式采纳并绑定。绑定强制提案 `round_id` 与决定产物的冻结 `artifact_round_id` 完全一致，只接受可验证的 AI 身份版本，并保留原 `created_by`、`member_version`、方法、阈值和模型置信度；它不会复制成 `created_by=user` 的新样本，也不会在绑定时读取行情。相同绑定幂等，跨轮、不同决定或不同组合版本冲突时失败关闭。
- 模拟组合 `confirms` 之后的验证是两个同级分支。前向观察新建时以 `tests(PROPOSED)` 绑定来源组合；用户确认后追加 `confirms`，真实基线可用时状态为 `OPEN`，不可用时为 `PENDING_BASELINE`；只有后一种情况在后续补到真实基线时追加可选的 `revises(OPEN)`；到期真实结算追加 `records_outcome(RESOLVED)`。历史 walk-forward 则以 `evaluates` 绑定同一组合精确版本。前向观察不进入 walk-forward 输入，不存在“观察先发生，所以导致回放结果”的因果边；一条轨也不能替另一条轨完成验证。
- `records_outcome` 只说明这一条观察按预先冻结条件得到一个真实结果。单样本无论命中与否都不等于稳定胜率，也不能绕过独立样本去重和最低 20 样本统计门。
- 只有既无 `decision_lineage_resources` 登记、也无谱系事件的迁移前旧组合、观察和回放才归类为 `LEGACY_UNLINKED`。资源已有登记但创建事件缺失、首次事件不符或决定绑定冲突时是谱系损坏，必须失败关闭，不能假装成从未关联。
- `decision_lineage_heads` 保存每个用户决定链的尾序号和尾哈希，补足前序哈希无法发现“最后事件整体被删”的缺口；`decision_lineage_resources` 保存资源到决定及首次事件的稳定绑定。关系表重建与两张登记表回填都在 `SAVEPOINT` 内原子迁移，异常会回滚临时结构、数据和迁移标记。
- 每个事件仍保存资源精确版本与安全快照，并用资源快照 SHA-256、`previous_event_sha256`、事件 SHA-256、持久链头和包清单 SHA-256 检查本地顺序及内容一致性。它们没有签名或独立外部锚定，只是本地一致性审计，不是外部防篡改公证，不能证明来源真实性、事实正确、因果关系或第三方不可抵赖性。
- `artifact_evidence_graph_v2` 的用户决定节点同时显示 AI 首选和用户选择；只有完整 `support` 才生成指向用户所选候选的 `selects` 边，`hold` / `return` 不生成选择边。
- 决定包、谱系事件和其安全快照固定返回 `execution_capability=none`、`live_trading_allowed=false`、`can_autonomously_decide=false`。决定包只能组织研究与模拟；用户仍是最终决定者。

## 证据门禁

- 摘要、每个候选方案、首选或暂缓理由，以及每条非空的结论、分歧、待验证事项、待办都必须至少绑定一个证据。
- 证据只能引用当前房间内真实存在的消息或资料版本。
- 每条证据关系必须明确用途：`support`（支持）、`counter`（反证）或 `context`（背景）。
- 每条证据关系必须明确核验状态：`unreviewed`（未核验）、`source_checked`（已核对原文）、`corroborated`（已交叉佐证）或 `disputed`（存在争议）。
- AI 生成、历史旧格式和刚冻结的官方资料默认都是 `unreviewed`；冻结只证明来源索引被保存，不代表内容已经证实。
- 交易研究产物中的 `round_market_snapshot` 还必须保持与轮次 manifest 相同的 source ID、revision、SHA、当前/启用状态及只读安全字段，并至少由用户标记为 `source_checked` 或 `corroborated`；缺失、漂移、未核验或安全字段异常都会阻止确认。
- 旧产物遵守只读迁移原则：列表、读取、证据装饰和失败的确认请求都不会偷偷新增证据或版本；用户下一次显式保存时才会创建新草稿版本并补入必需的冻结市场快照关系。
- 会议摘要、结论和待办至少需要一条用途为“支持”、且状态为“已核对原文”或“已交叉佐证”的证据。分歧和待验证项可只使用背景或反证，但仍必须完成状态标注。
- 反证或存在争议的证据必须填写核验说明，记录冲突、限制或为什么不能作为支持证据。
- 关系同时保存在结构化内容和 `artifact_evidence` 表中，便于查询与审计。
- `artifact_evidence` 同时保存用途、核验状态和说明；完整内容也随 `artifact_versions` 冻结。
- 编辑器按“会议摘要、首选方案选择、候选方案 N、结论 N、分歧 N、待验证 N、待办 N”分别选择证据，允许同一来源在不同条目中承担不同用途；最近消息与历史已引用来源都会保留在候选列表中。
- 资料证据固定引用具体版本。资料出现新版或被停用后，系统不会静默把历史引用升级到最新版，而是标记 `superseded` / `inactive`。
- 用户可以选择迁移到最新版；界面会把该关系重新设为“未核验”，要求检查新内容。也可以选择 `keep_snapshot` 保留历史版本，但必须在核验说明中写明为何该历史快照仍适用于当前纪要。
- 确认接口会在确认瞬间重新读取资料当前版本和启用状态，防止“保存草稿后资料发生变化”绕过版本检查。
- 缺少证据、仍有未核验证据、缺少支持证据或反证没有说明时，确认接口返回冲突并列出具体项目。
- 分歧必须保存状态 `open`、`resolved` 或 `accepted_risk`。阻断性的 `open` 分歧可以被确认成准确记录，但会阻止候选方案收敛；`resolved` 与 `accepted_risk` 都需要处理说明。
- 空白纪要不得确认。纪要至少包含非空摘要和已核对的支持证据；所有实际存在的结论、分歧、待验证事项和待办也必须逐条绑定并核验证据。

“用户已确认”表示用户确认了会议记录和证据关系，不表示所有事实都已经独立证实。导出的 Markdown 会逐条显示证据用途、核验状态和说明。

## 生成与诚实回退

- 整理成员优先选择决策阶段或具备 `decision_synthesis` 能力的成员，再回退到主持人或其他可用成员。
- DeepSeek 的会议整理调用使用官方 JSON Output 模式，并使用独立于普通成员发言的输出预算与超时；普通群聊调用不会因此扩大成本。其他适配器没有结构化能力时继续使用普通生成接口并接受同一服务端解析与校验。
- 模型只能引用提示中提供的消息 ID 和资料 ID，不能虚构来源、事实、统计胜率或真实交易动作。
- 模型不能自行把证据标记为已核验或已交叉佐证；服务端始终把模型选择的证据规范化为未核验，等待用户审查。
- 绑定正式轮次的生成请求先检查稳定 `generation_key`；幂等重放返回原草稿，Provider 调用为 0。
- 需要模型生成时必须复用该轮精确的 `scope=round` 调用账本、Provider 跳过策略和经过 SHA-256 完整性校验的冻结整理路由，并在上游请求前预留 `artifact_generation` 名额。整理路由固定成员 ID、身份版本、Provider 和已解析模型；轮后成员编辑、禁用或请求体指定其他成员都不能改写它。若账本仍有 `STARTED` 调用，纪要失败关闭并要求先走暂停轮恢复，不会擅自标记在途调用为遗留。
- 上游失败或结构无效分别记为 `FAILED / INVALID`，名额不退款；次数用尽时不访问模型，只创建带 `PROVIDER_CALL_BUDGET_EXCEEDED` 说明的诚实模板。
- 未绑定轮次且存在任何已配置 Provider 时，HTTP 入口拒绝模型生成；只有没有已配置 Provider 时才允许本地模板草稿。
- 轮次运行中服务端拒绝生成；部分或暂停轮只能生成明确标记为“不完整阶段记录”的草稿。

## 导出与安全边界

- 前端可把当前版本导出为 Markdown，并保留状态、版本和证据引用。
- 会议产物属于研究与模拟决策记录，不提供真实下单、交易解锁、投注、支付或其他资金动作。
- 产物确认和用户最终决定的历史都仅用于审计、协作与研究；任何界面文案、API 返回或导出内容都不得把它们解释为执行授权。
- 当前完整闭环验收不使用 OpenAI：生成和会前检查均保持跳过 OpenAI，不探测、不调用，也不回退。Futu 继续只提供只读证据；纪要中的模拟方案不是订单或执行授权。
