# 新闻正文、事件修订与市场解释候选

本轮基线为 PR #39 的 `9ca9db403114c3f5cd5d248ba35e898ac970f349`，开发分支为 `feat/news-event-evidence-20261029`。2026-10-29 只读远端核对时，PR #39 仍为 Draft、未合并、HEAD 与基线相同。本文件是候选实施记录，不是生产部署、来源恢复、模型质量或完整目标验收证明。

原始目标是贯通“发现消息 → 正文证据 → 事件更新 → 市场影响”，并交付来源覆盖表、字段兼容策略、必要验收、可读事件卡片及真实运行缺口。该目标包含后续持续运行与覆盖优化，不能缩减为已有离线测试。

## 来源覆盖

每个来源向界面提供名称、入口、证券范围、时间语义、访问策略、历史能力和健康状态。新增来源可明确启用，检查间隔可独立设置；既有 403、429、Retry-After、人工等待和失败退避继续生效，手动正文读取也受同一来源等待期限限制。SEC 还需要声明联系用途的 User-Agent，运行内共享请求限速；目录存在不证明网络或账户已就绪。

NVDA、AMD、上下游其他公司、BTC、授权快讯和聚合线索尚未加入本批目录。没有“全市场”覆盖承诺。候选已增加 SEC `submissions.files` 有界历史分页，状态与消息在同一成功事务保存；历史条目保持原始时间，默认不作为新突发事件自动分析。真实断线回补、历史窗口完整性与可证明的连续覆盖仍需独立验证；成功轮询、304 或读取档案页不能直接证明这些结论。

## 数据字段与兼容

复用现有新闻 SQLite 数据库，追加表，不新建平行权威消息库。现有 `items` 继续作为列表当前行；旧已读状态与独立 AI 预约／结果账本保留。

| 对象／字段 | 语义与兼容策略 |
|---|---|
| 原 `items.id`、`identity` | 保留源内文章身份；不以新模型、规则或抓取时钟重新定义 |
| `news_article_versions` | 追加不可变的内容版本；保存摘录、正文证据、附件范围、抽取版本、原始链接、前版 ID 与变化 |
| `news_article_observations` | 单独保留源时间、纯格式与追踪参数变化；相同连续观察不重复入库，观察回退保留新记录；这些变化不自动新建收费任务 |
| `published_at` | 来源明确给出的首次发布时刻；不再将 Atom `updated` 当作首次发布，不拿本机时钟补值 |
| `source_updated_at` | 来源声明的修订时刻；旧本地 `updated` 不静默改标为该字段 |
| `first_seen_at` | 保留文章第一次本机发现时间 |
| `version_seen_at` | 当前内容版本实际进入系统的时刻；旧条目今天修订可据此进入新任务 |
| `fetched_at` | 正文证据或摘录版本实际获取时刻；失败尝试另留回执 |
| `analyzed_at` | 当前明确证据版本得到结果的时刻；不是调用成功或供应商结算保证 |
| 旧库迁移 | 仅对迁移时仍存在的当前行建立明确标注的历史快照，版本可得时点为迁移观察时间；不伪造已丢失旧版，也不产生自动分析任务 |
| 精确旧结果读取 | 阅读与旧付费身份查询使用同一冻结文本；格式／追踪参数观察不会让旧结果失联后再收费 |
| `news_events`／`news_event_articles` | 相同规范 URL 或明确确认的原始出处关联事件；不按公司／关键词／主题直接合并 |
| 转载与独立依据 | 原始出处相同的转载保留各自条目、版本和关系；不将出处数冒充独立依据数；确认转载后只退役尚未发送的重复任务 |
| `news_analysis_tasks` | 持久任务含事件、文章版本、证据包、任务类型、触发原因与状态；支持分页和积压计数 |
| `news_article_tasks` | 重要公告正文读取独立持久队列；策略默认关闭，开启后只处理启用来源且采集已开启的当前版本；附件有独立策略开关 |
| 任务状态 | `pending/running/completed/needs_review/failed/unknown/skipped`；终态不自动回到待发送；新修订只跳过尚未发送的旧版任务，保留已发送未知结果 |
| 历史时点读取 | `event_detail(as_of=...)` 只返回当时已观察的不可变版本／出处／获取记录；后来的修订不得回填过去 |

正文状态区分 `headline_only`、`excerpt_only`、`full_text`、`partial_text`、`fetch_failed`、`access_restricted` 与经确认的 `retracted`。正文成功不代表附件读取成功。HTTP 410 只说明资源不可取得，不自行推断来源已撤回。已确认撤回进入复核状态，不能自动产生正常摘要。

失败读取保留 `last_fetch_attempt`，并保留之前已取得的正文；“上次读到了正文”和“这次读取失败”同时可见。段落、表格行及已读 PDF 页保持定位；PDF 文本读取不证明 OCR、图形或版式解析完整。长正文使用有界证据包，记录选择、截断、遗漏段落与实际范围，不直接将全文塞入原 16,000 字节请求。

## 与现有分析、研究资料的连接

自动正文策略默认关闭。明确开启后处理已保存的重要公告队列，要求采集和对应来源同时启用；正文工作线程与发现线程、AI 线程分别运行。成功读取按该来源间隔安排再检查，RSS 不变时也可发现正文数字更正。无变化的再次读取只追加尝试记录，不追加内容版本或收费任务；中断的 GET 可在保留未知尝试后重试，已发送的 AI 调用仍保持未知、不自动重发。经确认的撤回标记不会被后来的 HTTP 成功悄悄清除。

SEC 联系头由用户明确输入后才保存，启用 SEC 来源前必须完成设置。状态只公开“已配置／未配置”，不把联系文本回显到普通概览或诊断；没有自动制造联系地址或读取本地密钥配置。

事实阅读保留原 RSS 合同及已消费历史身份；正文使用明确的新证据合同。新证据版本不等于新的收费许可，仍经既有会话授权、36 次／24 小时及 3 元应用预约检查。预约不是供应商实际账单。正文读取与模型调用分开，慢模型不会占住来源抓取线程。

市场影响使用独立任务类型，绑定已有房间轮次、资料版本、证据清单和只读行情共同快照。预期／旧指引必须具有发布时间前可得性、出处、期间、单位、标的和原句；缺少材料保持未知。行情必须保留其采集及市场时点，过期或未通过校验的共同快照不得当成当前行情。用户明确请求市场分析才进入共享预算账本。

用户事件卡片展示正文／附件范围、版本时间、变化、出处及缺口；历史版本视图避免混用当前摘要和当前研究草稿。研究交接复用既有资料草稿入口，不因打开草稿启动模型。

## 可观察的质量与覆盖

`overview.quality` 提供过去 24 小时的来源实际结果、正文读取状态、有效时间样本延迟、积压及覆盖未知情况：

- 来源成功率只以已观察成功或失败为分母；仍在请求和中断未知另计。成功但无新增与请求失败分别记录。
- 正文完整率与可读文本率分别列出；部分文本不算全文成功。没有读取尝试时比率为空。
- 来源发布到发现、发现到正文就绪、证据到结果分别提供样本数、p50、p95。仅采用明确来源发布时间、顺序有效且非迁移伪造的样本；结果延迟还要求实际结果引用，复用旧结果不造新延迟。
- 订阅窗口／最近申报范围的连续覆盖仍为未知。监督缺口与来源检查缺口保留，不能解读成停机时长或全市场漏报量。
- 重复提醒率、错合并率、证据支持率、重大误述数、单有效事件真实成本及相对覆盖率，没有独立判定样本／真实账单时返回空值和原因，不能显示为零。

这些是本机观测的运行统计，不能代替来源真实可用性、独立内容质量判断或供应商费用验收。
