# 独立 Windows 启动入口与回执命名契约

## 目的与本轮缺陷

本入口将已经本机验证的 CIM 启动方式保存为可版本核对的源码，供独立短窗和全天窗口使用。运行候选、退出记录器及启动入口各有自己的身份和 CI；启动入口不会替换模型、迁移旧数据库或恢复旧窗口。

2026-10-10 的新短窗真实激活后，独立观察器以 `host_receipt_ambiguous` 和退出码 2 提前结束。启动材料新增的 `host-job-boundary.json` 和真实 `host-<session>.json` 同时匹配观察器保留的 `host-*.json`。等待层要求最多一份，活动层要求恰好是已绑定的那一份。宿主后来正常生成停止回执和报告，不能据此抹去观察器失败。

修复在启动入口：四类边界回执统一使用 `job-boundary-<role>.json`，角色只能是 `launcher`、`observer`、`host`、`independent-recorder`。观察器的严格发现规则保持不变。旧目录、原始失败、报告、源码候选均保留，禁止在旧目录改名后冒充原运行已通过。

## 三份入口源码

| 文件 | 职责 |
| --- | --- |
| `scripts/start_news_review_isolated.ps1` | 通过本机 CIM 创建隐藏的启动入口，明确使用 `WinSta0\Default`，只传递白名单系统环境；创建成功本身不证明隔离 |
| `scripts/capture_news_review_isolated.py` | 在同一启动进程里执行 Python 入口，排他保存非秘密输出并同步，不接收密钥 |
| `scripts/launch_news_review_isolated.py` | 原生确认身份、存活、会话、作业和当前桌面；检查封闭材料；先启动并绑定观察器与 X-05，再释放宿主本机隐藏输入窗口 |

部署材料使用三份源码的原始字节副本，不能包含个人目录硬编码。`isolated-launch-bindings.json` 的唯一字段为：

```json
{
  "version": "news_review_isolated_launch_bindings_v1",
  "candidate_workspace": "<明确授权的绝对候选目录>",
  "recorder_script": "<固定X-05源码的绝对路径>"
}
```

该绑定文件、三份源码、窗口范围、策略模板、激活方案、联系 User-Agent、三个 CI 核对文件都必须在准备清单中。用户批准绑定该清单的原始文件 SHA-256。运行候选还必须是准确 HEAD 和干净工作区，X-05 源码必须为 `19d20dcabccabd8c37c3366311b152ff6dc3c60bce72cfba1763007ad6b01859`，记录器候选固定 `204f781b3599138725d605626f48a0f23ac3c232`。

`launcher-ci-verification.json` 包含启动入口的 `candidate_sha`、`evidence_reviewed: true`、准确候选的两条 `workflow_runs`，及 `source_files` 三个入口文件名到 SHA-256 的映射。运行、记录器、启动入口的两条 CI 均要独立核对全部九项交付步骤 completed/success。不能把旧 CI、未完成 CI 或不同候选的 CI 用作本候选通过依据。

## 使用与拒绝边界

先准备新目录、来源范围、预算、具体激活资格期和可审阅材料，再执行。诊断模式只核对本进程，不读取窗口范围、初始化产品或打开密钥窗口：

```powershell
& '<PowerShell 7绝对路径>' -NoLogo -NoProfile -File '<入口副本目录>\start_news_review_isolated.ps1' `
  -RunRoot '<本次新目录>' -AuthorizedWorkspace '<授权工作区>' `
  -PythonPath '<Python绝对路径>' -Mode check
```

真实激活使用同一参数将 `-Mode` 改为 `launch`；还必须具有已封闭的批准、准备清单、三个准确候选 CI、观察计划及全新 `NewsReviewTrial` 运行根。诊断模式不能充当真实运行通过证据。

仅允许两种既有授权模式：15 分钟、最多 2 次模型调用、应用估算 0.50 元；24 小时、最多 8 次、2 元。正文最多 16 次，请求最多 32768 字节，输出最多 1400 tokens，并发 1，仅 SEC NVDA 8-K 和 Micron recent-30。仍使用豆包 260915 Responses；UNKNOWN 停止，窗口内恢复关闭。来源时效标准在观察计划中分别绑定 SEC 15 分钟、Micron 30 分钟。

四个入口进程都核对 PID 加创建 ticks、原生句柄存活、同一用户会话和不属于任何 Windows 作业。启动器另确认其进程窗口站和线程桌面，不能把此检查冒称为已经看到密钥输入框。应用内部合法 worker 的既有治理保持原有语义；四个入口的作业要求不用于历史 B 轮归因。

宿主先停在一字节非秘密门闩。只有观察器已就绪、宿主与观察器的 X-05 原生目标绑定文件已出现、记录器自身也通过原生边界检查后，才写入 `G` 并打开产品的本机隐藏输入。入口不读取输入框、密钥、旧进程环境或凭据。输入取消、资格过期或边界无法证明时，保留失败，不自动重试。已激活的运行不能恢复、延长或拼接。

入口只在自身生命周期内保持系统唤醒，最终释放，不修改持续性电源配置。它等待实际进程退出；观察超时不代表目标已终止，也不会杀死宿主或付费 worker。未释放的门闩只允许关闭本工具自有的 stdin；产品尚未启动时，bootstrap 自行退出。

## 验证与验收层次

`tests/test_news_review_isolated_launch.py` 使用临时合成文件及真实观察器等待层、活动层准备逻辑。它复现旧命名两处拒绝、验证新命名两处通过，并保留两份真实宿主回执仍被拒绝的负例；同时核对不可恢复、身份精度、会话、作业查询失败、清单完整性、预算和模型边界、三个 CI 候选与步骤、源码哈希及排他回执。

本轮 19 项新增离线检查通过；与既有观察器等待层、活动层组合回归共 85 项通过（包含这 19 项），网络审计所有连接和阻断计数为 0。另有既有静态基线 7 项通过，不能冒称完整安全审计。本机另用当前三份源码实际运行 CIM 诊断，确认会话 1、`WinSta0\Default`、不属于任何作业，持有创建 ticks 匹配的同一原生句柄直到真实退出 0；没有来源、模型或数据库请求。第一次沙盒测试受 Windows 临时目录权限拒绝影响，结果无效并保留披露；随后使用同一隔离运行器在正常临时目录通过。测试模块最初直接导入夹具类导致重复发现既有用例，已改为模块导入，正式计数不混入重复用例。

这些证据仍不等于全天连续运行、来源公告完整捕获、在途模型排空、模型质量、账单核验或发布批准。新的真实组合要按自己的批准和新目录执行，核对激活前就绪、宿主停止和排空、报告哈希、观察器终态、两个 X-05 目标、记录器读回后 stdout 与真实退出码、宿主及已绑定 worker 原生终态。未核实项保留 UNKNOWN，不能靠退出 0 或缺文件补成通过。

当前失败短窗的 SEC/Micron 各 3 次完整轮询和绑定终态时效，可作为该短窗范围的真实证据；它们不是 HTTP 总数或公告捕获率。该短窗模型调用为 0，整体验收未通过；旧 36 项人工评分 7.25、质量门槛 False 保持。质量提示候选 `ae820944` 必须有新输出和独立重新评分，合成成绩不能冒称自然新闻审核能力。
