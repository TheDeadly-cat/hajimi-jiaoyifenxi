## 明确选择与既有结果

- 默认仍为豆包，旧三参数配置接口继续有效；新接口只接受固定 provider/model 组合，不允许自定义端点、重试、搜索或其他工具。
- 选择新模型会清除尚未提交的密钥、费用确认和自动分析选项，重新输入并确认后才启用；运行中禁止切换。界面分别显示当前启用模型和保存结果所属模型。
- 保留原豆包 v3、冻结 v2、legacy 指纹公式和历史读取优先级，再查询新增固定模型身份。同一材料任一已完成、失败、处理中或未知记录都阻止自动重发，不因切换平台重置费用。
- 队列携带配置代次，切换、清除、授权到期会废弃旧队列。预约与跨模型重复检查在同一 SQLite 写事务中执行，两实例竞争同一材料或最后剩余次数时也只允许一份有效预约。
- 新候选只给独立审核库追加 provider、model、contract、rate_version、reservation_basis 五列。旧已完成/失败/未知记录的原六列及 JSON 不回填、不改写；旧 pending 在构造时转 unknown 的既有恢复行为保留，不能声称重启后 pending 逐字不变。生产库本轮未打开或迁移。
- 当取消的 queued 占位得到后端明确“无结果、未配置、不忙碌”确认时解除界面锁定；不能以超时、缺字段或普通错误清掉真正的 pending/unknown 并允许重复请求。

正常分析界面没有“换模型再收费重分析”按钮。未来有意做同材料对照，须在新独立比较库、单独批准的样本和次数范围内进行，不覆盖生产结果。

## 供应商协议与费用控制

新闻专用适配器使用固定 Responses 端点，保留豆包原请求字段并沿用标准代理行为，不导入会读取配置文件的通用供应商模块。DeepSeek 显式关闭思考模式；两者均使用 v3 JSON Schema、最多 900 个总输出 tokens、45 秒 socket 超时、16,000 字节请求体限制和 2 MiB 响应限制。不重定向、不自动重试、不跨平台失败回退、不提供搜索工具。socket 超时不冒充整个调用的硬墙钟期限。

只有完整 completed 响应、文本输出和与所选模型族匹配的报告身份才能进入内容校验。允许已知滚动版本名称；未知、跨供应商或 Flash→Pro 的身份报告明确失败，预约保留且不重试，不把请求模型补写成已确认的报告模型。内容还必须通过原句及关系措辞检查，HTTP 200 不代表审核质量通过。

三路模型共享原有近 24 小时 **36 次 / 3 元**应用预约预算。请求与预约使用同一 UTF-8 编码函数，输入按请求字节数加 256 估算，输出预留 900 tokens，金额向上取整到微元。豆包沿用现有应用预约参数；DeepSeek 使用官方美元峰值费率、忽略缓存和低峰折扣，以 **10 元/美元**作为保守预算参数。它不是实时汇率，也不是供应商账单硬上限；真实账单和价格需在获准调用前重新核对。

官方依据：[DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)、[Responses API](https://api-docs.deepseek.com/api/create-response/)。本轮未验证真实账户权限、接口连通性、返回质量或供应商账单。
