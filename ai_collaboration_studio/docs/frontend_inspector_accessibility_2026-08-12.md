# 房间检查器键盘可访问性验收（2026-08-12）

## 问题与结果

移动端打开“房间信息”抽屉后，焦点原先仍停留在背景触发按钮；点击关闭后焦点落到 `body`。这使键盘用户能够失去当前操作位置，也没有形成清晰的模态抽屉边界。

现已形成完整闭环：移动端抽屉按断点获得 `dialog` / `aria-modal` 语义，打开后聚焦关闭按钮，Tab 与 Shift+Tab 在抽屉可见控件内双向循环，Escape 或关闭按钮退出后把焦点恢复到精确触发器。宽屏检查器继续作为常驻非模态侧栏，不声明 `dialog`，也不抢走页面焦点。

## 实现边界

- `frontend/src/App.jsx`
  - “房间信息”触发按钮增加 `type`、`aria-controls` 和稳定抽屉 ID。
  - 使用单一 1180px 宿主断点同步视觉布局与可访问性语义。
  - 仅在紧凑布局且抽屉打开时安装一个键盘监听器；关闭、切换断点或卸载时立即清理。
  - 初始焦点、双向循环与恢复焦点均使用精确 ref，不依赖定时猜测或全局选择器。
- `frontend/tests/inspectorAccessibility.test.js`
  - 固定模态语义、触发器关联、初始焦点、双向焦点循环、监听器清理和精确焦点恢复。
- `frontend/tests/codeSplitting.test.js`
  - 继续保证移动端标题在足球/股票懒加载面板之前。

上述修改不改变房间、材料、领域合同、正式轮授权、Provider、市场连接或用户决定逻辑。

- URL：`http://127.0.0.1:18774/`，系统临时 runtime 与显式临时 SQLite。
- 390×844：抽屉 `role=dialog`、`aria-modal=true`，初始活动元素为“关闭房间信息”。
- `Shift+Tab`：从首控件循环到最后一个可见有效控件“整理会议草稿”。
- `Tab`：从最后控件循环回“关闭房间信息”。
