# AI 共创室 V2 目标架构

## 产品边界

主产品是通用多 AI 群聊，不是股票分析器。交易研究、体育研究、项目研究和方案共创共享同一套房间、成员、消息、材料和产物机制。

```text
AI 共创室
├─ 通用共创
├─ 交易研究
│  └─ 美股
│     └─ 美国存储产业投资委员会
├─ 体育研究
└─ 项目研究
```

存储产业房间研究 `US.MU`、`US.SNDK`、`US.WDC`、`US.STX`，但它只是“交易研究 / 美股”大类中的一个可复制、可编辑小群聊。模板只提供默认成员、分类和能力包；通用核心只识别房间的能力合同，不以 `us_storage_committee` 之类的模板 ID 分支领域行为。

## 核心实体

- 房间：层级化 `category_path`、长期目标、场景规则、讨论模式、模板来源、持久化 `capability_pack_ids`、服务端派生的只读 `capabilities` 和可编辑 `workflow_policy`。
- 成员：显示名、身份、职责、边界、立场、专业能力、流程阶段、模型执行器、模型、启用状态和顺序。
- 流程政策：配置阶段顺序与最低覆盖、必须听到的立场/能力、不同成员总覆盖、每成员发言上限和追加追问预算；模板只提供默认值。
- 身份版本：每次修改递增版本；历史发言保存发言时的身份和版本。
- 轮次：本轮目标、完成状态、失败成员、冻结的 Provider 禁用策略、新正式轮必备且由 round/checkpoint 权威保存的 `turn_contract_version + turn_envelope_version + schema SHA-256 + execution_audit_version`，以及按轮次内序号追加的主持决定、`round_turns` 发言账本和持久化 trace anchor 链头。新主持决定带 canonical `decision_sha256`；“只追加”是服务端正常写入合同，不是对恶意数据库管理员的物理不可变保证。
- 消息：用户、AI 与系统事件共用可追溯时间线；新正式轮从纯 JSON `turn_envelope_v1` 中分离可见正文与规范化 `turn_contract_v1`，再原子保存合同、合格状态和安全问题码。旧 XML 合同与无合同消息保持原版本兼容，暂停恢复不回填新协议。
- 材料、产物与验证：富途共同快照、资料版本、消息引用、会议纪要、分歧、待办、证据门禁、产物确认、与产物精确版本及用户所选候选绑定的最终决定、`decision_package_v2` 决策研究谱系、1/5/20 交易日模拟观察，以及固定纸面组合历史滚动回放均已接入。

通用内核包含 `collaboration.chat`、`materials.shared`、`artifacts.meeting` 和新正式轮强制的 `turn_contract_v1` 审计协议。房间创建时只能从服务端 `CAPABILITY_PACKS` 白名单选择领域包，选择结果持久化并独立于成员模板。领域包清单同时声明专业能力、成员讨论规则和主持调度重点；因此它既控制专业入口，也约束动态协作方法。`structured_turn_contract_v1` ID 只为历史房间和版本快照兼容保留，并在界面中作为系统管理协议展示；结构化项目研究包提供需求证据地图、候选方案矩阵、风险登记和条件化项目建议；存储研究包声明 `market.storage.readonly`、`analytics.storage`、`simulation.observations`、`simulation.paper_portfolio` 和 `decision.observation_proposals`。包目录、房间创建和更新都强制验证 `execution_capability=none` 与 `live_trading_allowed=false`，未知或可执行包失败关闭。

## 领域适配层

通用房间内核只编排成员、轮次、主持、消息、材料和产物，不直接导入存储市场服务，也不在通用成员、主持或产物提示中固化富途、存储标的、交易研究或投委会语义。能力包是声明式合同；需要读取专业数据、注入领域上下文、解析领域机器块或扩展产物证据类型时，再由 `DomainAdapterRegistry` 激活对应的领域适配器。

- Registry 按适配器的 `activation_capabilities` 与房间冻结能力的交集解析活动适配器；对于声明了强制映射的能力，未知或缺失适配器会失败关闭，不能静默退回通用逻辑。
- 注册与每次解析都会重新验证安全合同。所有领域适配器必须声明 `execution_capability=none`、`live_trading_allowed=false`，并提供完整接口；不安全、未知或接口不完整的适配器不能进入轮次。
- 提供行情上下文的适配器另声明 `provides_market_context=true`。Registry 仍按能力交集选择，未命中能力时不激活；同一房间命中多个行情适配器时失败关闭，最多只允许一个冻结数据来源进入该轮。
- 当前 `StorageResearchDomainAdapter` 独立拥有存储行情会前预检、冻结提示上下文、时间线系统消息、结构化观察提案规则与解析、提案持久化，以及会议产物的冻结行情证据说明。`DiscussionOrchestrator(..., market_service=...)` 仅保留为测试和既有调用的兼容注入点，不重新建立通用内核对存储服务的直接依赖。

运行时执行边界不依赖提示词或单一静态黑名单：所有 HTTP 请求先经过执行型路径拒绝策略；所有模型 POST 由统一构造器生成，载荷只能是文本生成并递归禁止工具/函数调用键，目标 URL 也不能含账户、订单、支付、钱包、转账等执行段。源码 AST 审计负责发现驼峰调用、常量拼接属性及绕过集中构造器的原始写 HTTP，但它只是纵深防线；实际主边界仍是无交易 SDK、能力包失败关闭、HTTP 运行时策略和文本型 Provider 请求的组合。

房间创建后仍可编辑名称、目标、分类、调度模式、显式主持成员和能力包。更新使用 `settings_version` 乐观并发门；轮次检查点 v7 冻结当轮 `discussion_mode / domain`、隐藏主持 ID/身份版本/Provider/模型、能力包、派生能力与项目工作区缺口，v8 增加候选精确版本风控 marker，v9 再冻结 envelope 版本、schema SHA-256 与逐成员输出模式。暂停恢复继续使用原协议、隐藏调度路由、能力和缺口；普通成员（包括承担主持身份的成员）的下一次可见发言读取用户最新编辑的身份、职责与边界，但正式轮 Provider / 模型及输出模式由调用账本中的确认路由决定。缺少完整主持路由的早期 v7 检查点失败关闭，v6 及更早检查点继续使用原有的流程首阶段主持兼容规则。

## 动态讨论

1. 主持人先明确本轮目标和评价标准。
2. 服务端先以 `rules_first_director_v2` 处理可证明唯一的调度：首位定界后，先开放“已满足阶段 + 最早未满足阶段”的因果前沿，再将前沿内成员按其对阶段、职责、独立发言者及当前证据/项目缺口的贡献进行比较。某阶段最低覆盖完成后，剩余该阶段成员可与下一阶段共同竞争；风险与决策阶段不能越过尚未形成的方案。唯一最高贡献、唯一可执行成员和安全收敛均不调用模型。只有多个候选贡献仍并列且预算允许时，隐藏调度器才根据最新讨论、候选成员职责、房间政策和未覆盖风险选择下一位；结构化项目房间仍从冻结工作区派生 `evidence_review`、`critical_review` 或 `decision_synthesis` 缺口，不把交易领域逻辑写进群聊内核。
3. 服务端按房间政策检查阶段、立场或专业能力覆盖；存储模板默认要求多头、空头、风控等公司职责，但其他房间可自行配置。
4. 规则优先决定以 `source=rules_first` 审计，并明确记录 `service_policy / model_used=false`。调度模型失败、Provider 身份不匹配、JSON 无效、返回非候选成员或越过收敛门要求结束时，先把调用结果写入 `director_attempts`；不可执行但 JSON 合法的决定同样是 `INVALID`，不是成功响应。同轮同一冻结路由首次 `FAILED / INVALID` 后立即熔断，后续不再调用该路由；系统按当前缺口贡献与稳定顺序回退，并把决定来源标记为 `director_circuit_breaker`。确认计划中的 `recommended_director_calls` 会封印为 `round_director` 硬子预算；额度为零、原子预留时子预算竞争耗尽，或全局余额只够完成最少强制可见发言时，都不调用主持 Provider。每条新 `director_decisions` 继续绑定经过白名单清洗的 `director_moderator_context_v1`，并将有界 `director_scheduling_context_v1` 一同纳入决定 SHA-256：模型看到的候选、持久化候选和路由授权共用 256 个成员的单一上限，只保留候选 ID、缺口代码、候选贡献、最少剩余可见调用、预算余量、`target_stances`、修复范围和规则标识，不持久化共享正文或模型提示；历史空字段不回填。
5. 成员在轮次中被修改后，从其下一次普通发言开始读取最新身份、职责和边界；正式轮已经确认的 Provider / 模型仍从同一调用账本的成员路由封印读取，轮中路由热改只影响下一新轮。Provider 禁用策略在实际调用边界重新检查，不能通过热改绕过。已持久化的结构化点名按点名时 `member_version` 读取身份，同时仍受本轮确认路由约束；当前成员用于确认仍启用。
6. 阶段顺序既是语义依赖，也是并列时的稳定信号，但不是“把同一阶段所有成员依次轮询完”的硬过滤器。前沿阶段达到最低覆盖后立即开放下一阶段，尚未发言的早期成员仍可凭更高缺口贡献再次胜出；强制覆盖与收敛门已经满足后，不会只为清空可选成员名单继续调用。前置阶段不可修复时允许继续收集下游审计观点，但最终状态保持 `PARTIAL`；冻结研究缺口标为 `repair_scope=next_round_only` 时，由匹配职责成员说明一次影响和下轮补证条件，随后以 `partial_unrepairable` 零调用结束。首轮覆盖后进入“追问与修订”，主持人仍可因用户插话、点名或真实新反证重新安排有预算成员。
7. 每轮启动时冻结完整政策和项目缺口快照，暂停恢复继续沿用原快照；房间政策或项目产物修改只影响下一新轮。同一房间只允许一条活动轮次，防止多标签页交错写入。
8. 每次选择下一位或建议结束都先追加到 `director_decisions`，再发送完整流事件。记录保留动作、成员、理由、来源、阶段、关注点、冻结主持上下文与单调递增序号，并以 `decision_sha256` 封印记录身份、归属、内容和创建时间；持久化失败时轮次失败关闭，刷新和恢复不能丢失主持依据。升级前缺少决定封印的历史记录不回填，执行轨迹据实降级为 `partial`。
9. 发言者与隐藏调度器读取完整当前轮记录。超出上下文预算时，最近消息保留原文，较早消息按稳定顺序压缩成逐条索引；每条历史发言仍有可识别位置，不使用固定 28/36 条窗口静默丢弃早期反证。
10. 每个新正式轮都把 AI-to-AI 回应图作为服务端 `turn_contract_v1` 合同，并用纯 JSON `turn_envelope_v1` 承载合同与可见正文。首位成功 AI 可无回应边，之后每条成功发言必须回应同轮此前成功的正式 AI 消息，并声明支持、质疑、限定或追问。允许证据引用的消息前缀与必须回应的 AI 前缀分开冻结；用户开场、失败系统事件和非正式插话不能冒充 AI 回应目标。第一条合同回应投影为真实群聊回复边，持久化重放同时核验合同、回复 ID、回复人名、envelope schema 与冻结输出模式，漂移即阻断产物收敛。

## 调用预算与执行审计

新正式轮在用户确认 `round_launch_plan_v3` 后创建唯一 `provider_execution_runs`。其中 `provider_execution_policy_v1` 与 SHA-256 一起冻结 `kind_call_limits.round_director = recommended_director_calls` 和 `operation_binding_version = provider_operation_binding_v1`。美国存储样板的当前建议是 6 次主持调用、21 次总授权；6 是主持类型的硬上限，21 是建议的全局授权值，用户明确确认的全局上限仍独立存在。每次预留先检查全局上限，再检查该类型是否配置了更窄的子预算；`FAILED / INVALID / CANCELLED / ABANDONED` 与成功调用一样占用已预留的全局名额，主持尝试还占用 `round_director` 名额，均不退款。运行时用当前未满足的阶段、职责、独立发言者和工作区缺口计算一个确定性的最少剩余可见成员调用数；全局余额小于或等于该数时，隐藏主持必须走零调用规则或安全回退，不能消耗留给正式成员的推进槽位。

每个新正式轮中的实际 Provider attempt 在发出网络请求前获得服务端 UUID4 `operation_id`。`operation_binding_sha256` 同时覆盖 run、attempt、序号、kind、Provider / 模型、成员版本及精确业务目标；允许的映射只有 `preflight_probe → provider_route`、`round_director → director_attempt`、`round_speaker → round_turn`、`round_interjection → chat_request`、`artifact_generation → artifact_generation`。路由目标使用规范路由哈希，纪要目标使用稳定 `generation_key`；其余目标必须属于同一房间和轮次并匹配已批准成员路由。这样可以证明本地账本中“这次预留尝试声称服务于哪个对象”，不再用时间邻近猜测 attempt 与主持、turn、插话或产物的因果关系。

`round_execution_trace_v1` 仍是既有事实表的只读投影，不拥有 Provider 或交易执行能力。新正式轮标记 `round_execution_audit_v1`，在进入 `PAUSED / COMPLETED / PARTIAL / CANCELLED` 时调用 `seal_round_execution_trace`：把非敏感轨迹快照、来源水位及其哈希追加到 `round_trace_anchors`，链接 `previous_anchor_sha256`，并以条件更新原子推进 `rounds.trace_anchor_head_*`。同一快照重复封印不新增记录；暂停后恢复产生的新记录会让当前快照暂时标记为“自上个锚以来已变化”，直到下一安全边界追加新锚。

兼容边界必须诚实：升级前轮次不会回填 operation ID、主持决定封印或 `round_execution_audit_v1`，因此轨迹保持 `partial`；运行中的新轮也可能因锚尚未生成而暂时 `partial`。这些 UUID、摘要与 append-only 约束只在本地服务和同一 SQLite 的一致性模型内提供局部防篡改证据。数据库管理员若能同时改写业务行、摘要、锚记录和轮次链头，仍能重造一套自洽历史；本层没有私钥签名、数据库外 HMAC、外部时间戳或第三方锚定。

## TradingAgents 复用边界

适合吸收：

- 分析师 → 多空研究 → 交易员 → 风控 → 组合经理的阶段门。
- Bull/Bear 反方辩论和风险复核。
- LangGraph 条件边、检查点、结构化决策与失败恢复思想。
- 多模型 provider registry 和交易数据验证机制。

不直接照搬：

- 固定角色名称和固定拓扑。
- 单标的 CLI 作为产品入口。
- 把模型评分当作真实胜率。
- 任何真实订单发送路径。

## 下一阶段顺序

已完成第一层富途接入：严格白名单、统一批量快照、历史日线、数据质量标记、同轮快照冻结和只读执行边界。

共享材料与引用证据的第一层也已完成：`materials / material_versions / message_citations`、手工资料录入、版本冻结和无效引用拦截。

这些 SHA-256 摘要、Provider operation 绑定、主持决定封印、trace anchor 与业务数据保存在同一个 SQLite 中，只用于发现未同步改写摘要或链头的本地损坏、局部篡改和降级，不构成数字签名或外部防篡改公证。若未来威胁模型包含可同时改写数据库内容、摘要、锚链与链头的管理员，需要把 HMAC/签名密钥或 ledger 锚根放到数据库之外。
