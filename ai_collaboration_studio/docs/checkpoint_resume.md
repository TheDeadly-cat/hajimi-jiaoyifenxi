# 轮次检查点与失败续跑

## 目标

长轮次不应因为用户暂停、浏览器断流或服务进程中断而从头重跑。检查点只服务讨论恢复，不扩大模型、行情或资金权限。

## 保存内容

每个轮次在创建时和成员状态落定后更新一个 SQLite 检查点：

- 原轮次成员 ID 集合；
- 已发言成员及次数、已覆盖立场、上一位发言者；
- 完成、失败、跳过和观察提案计数；
- 下一步序号与最大轮次；
- v7 在创建轮次时冻结的 `discussion_mode`、`domain`，以及隐藏主持成员 ID、身份版本、Provider 和模型；未显式指定主持时，冻结当时流程首阶段成员及其路由；
- 创建轮次时冻结的房间 `capability_pack_ids` 与派生能力清单；
- 创建轮次时冻结的项目工作区缺口、首要焦点及适配成员能力；只保存计数和缺口说明，不复制完整产物正文；
- 创建轮次时冻结且实际传给成员的共享提示上下文；
- 同轮富途只读行情快照。
- `round_evidence_manifest_v1`：本轮纳入/省略的资料、确切版本与哈希、提示截取长度、共享上下文哈希，以及市场快照 ID、证据版本、快照哈希和只读安全字段。

不保存模型密钥、请求认证头、浏览器 Cookie、账户或真实交易信息。共享提示在任何模型调用前限制为 30,000 字，并以实际落库值回读校验；检查点整体限制为 512 KiB。超过整体上限时，新轮在调用模型前取消并明确报错，不留下持续运行的轮次。房间 API 只暴露步骤、计数、已覆盖成员 ID、检查点/清单版本、冻结能力包、冻结能力、冻结项目缺口和冻结资料数量，不向前端返回冻结提示正文。

## 状态机

- `RUNNING`：当前流正在执行。
- `PAUSED`：流在完成前关闭；结构有效的检查点保留，可继续，也可由用户明确结束。
- `COMPLETED`：所有必要成员成功完成。
- `PARTIAL`：轮次完成，但存在成员失败或跳过。
- `CANCELLED`：保留给明确废弃且不再恢复的轮次。

只有 `PAUSED` 且存在检查点的轮次可以调用恢复接口。每次恢复递增 `resume_count`，使用同一个 `round_id`，不会新建或重复用户消息。

房间级新轮锁读取独立的 `pending_round`，不把“时间上最新的终态轮”误当成恢复权威。用户调用 `POST /api/rooms/{room_id}/rounds/{round_id}/cancel` 可把暂停轮明确改为 `CANCELLED`；消息、身份版本、检查点和审计轨迹仍保留。进程启动恢复时，只有严格可校验检查点的遗留运行轮转为 `PAUSED`，无检查点或损坏检查点的遗留 `RUNNING / PAUSED` 轮次改为 `CANCELLED`，避免生成没有恢复或退出路径的死锁状态。

## Provider 调用授权恢复

每个新授权轮次必须绑定唯一的 `scope=round` Provider 调用账本。账本除 `plan_hash`、上限和跳过策略外，还以 `provider_member_routes_v1` 保存并哈希封印启动计划中的全部 `{member_id, approved_member_version, provider, model}`。恢复接口按房间、轮次和 scope 精确查找原账本，继续使用同一成员路由封印，不接受新的上限、模型或路由，也不补充已经消耗的名额。没有该账本的迁移前暂停轮保持 `PAUSED` 并失败关闭；没有新路由字段的旧账本保留兼容读取语义，但新正式轮一律写入完整封印。

恢复前，账本中遗留的 `STARTED` 调用统一终结为 `ABANDONED`；该名额不退款。恢复后的真实预检、成员发言和主持调用继续从同一剩余次数原子预留。无成员预检只能使用封印清单中的 Provider / 模型组合；带成员调用还必须匹配该成员的确认路由，路由清单或哈希损坏时不会访问 Provider。次数用尽时以 `PROVIDER_CALL_BUDGET_EXCEEDED` 安全暂停。

## 一致性边界

恢复时允许读取成员最新身份、职责、边界和启用状态，使用户暂停期间的明确身份调整从其下一次普通发言生效；普通成员的 Provider / 模型由原轮账本确认路由覆盖，暂停期间的路由编辑只影响下一新轮。隐藏主持调度继续使用检查点冻结的成员版本、Provider 和模型。HTTP 恢复预检遵守同一分离语义：普通成员按账本确认路由检查，隐藏主持按检查点精确身份版本和冻结路由检查，不能用当前房间主持替代，也不会为只影响下一轮的路由产生无关探测。`discussion_mode`、`domain`、主持路由、流程政策、房间能力包、派生能力、项目工作区缺口、市场快照和材料上下文均保持原轮次版本，避免不同成员落入不同规则或数据截面。冻结主持被停用时恢复失败关闭，不会静默换主持；暂停后修改房间主持或调度设置只影响下一轮。缺少完整冻结路由的早期 v7 检查点会以 `ROUND_CHECKPOINT_INVALID` 失败关闭且不调用 Provider；v6 及更早检查点继续使用原有的隐式首阶段主持兼容规则。

隐藏主持调用使用独立 `director_attempts` 账本。调用开始前登记 `STARTED`；正常响应只有在 `director_decisions` 已落库且普通发言 `round_turns` 已预留后才登记 `RESPONDED`。上游失败、Provider 身份不匹配或 JSON 无效分别登记 `FAILED / INVALID`，同轮同一冻结路由随后熔断并确定性回退，不再重复调用。暂停时在途有效结果登记 `CANCELLED`；进程退出留下的无 token `STARTED` 只允许在明确恢复 `PAUSED` 轮次时以 `director_attempt_abandoned` 终结，记录不会删除。

恢复状态切换前，服务端先校验清单结构、每个历史资料版本的正文/快照哈希、完整共享上下文哈希、市场快照哈希及只读字段。任何一项不一致都会返回 `ROUND_EVIDENCE_INVALID`，轮次保持 `PAUSED`，`resume_count` 不增加，也不会调用模型。

新轮首次检查点保存后会立即回读并按同一规则复核，之后每次进度保存都原样携带同一清单。资料引用的确切版本和观察提案使用的资料版本/市场快照由服务端绑定，模型不能自行指定。

正式轮次纪要必须复用这份检查点和证据清单：只选择相同 `round_id` 的消息及其成员身份版本，并按清单读取材料确切版本，不能在纪要生成时重新抓取行情、读取轮后消息或改绑资料最新版。存储投委会只有在 12 个正式职责均成功覆盖后才可确认正式纪要；不完整轮次最多生成标记为 `DRAFT` 的复盘框架。

如果进程在普通成员模型调用边界中断，唯一 `round_turns` 记录会在恢复时按“结果未知”失败关闭，不重放该成员调用；已经持久化的成员失败继续隔离并推进其他成员。隐藏主持的遗留 `STARTED` 会先显式取消，再由恢复后的新安全调度边界决定是否发起新的审计调用；新主持调用必须从原轮账本剩余名额再次预留并消耗一个新名额。
