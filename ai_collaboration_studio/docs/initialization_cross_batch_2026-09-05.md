# PR A：SEC/IR 初始化策略的跨批语义

基线：`25f61d00e3ec49e9034dfc3139033e4ff3b3487e`。
工作分支：`codex/initialization-cross-batch-20260905`。
本轮只修复初始化范围与投递额度的混淆，保留 Runtime、Scheduler、Broker、来源范围和默认开关。

## 行为合同

初始化历史是第一次成功分类时，官方完整有界查询中实际存在的身份集合；不是全市场或全历史。
SEC 沿用 selected-form recent 范围，IR 沿用完整已读取 feed/Q4 范围，容量仍为 1,000 / 250。

- `seed_only` 沿用已完成的完整基线，不导入初始历史。
- `catch_up` 在整个初始历史中按事件时间降序、fingerprint 升序选最多 N 个身份。无论分几批，初始历史导入总量不超过 N。
- `from_time` 仅在完整初始历史中做一次排除；被排除身份或 IR 投影保留在 checkpoint，不能在后续批次重新涌入。
- 单批仍同时受 `per_symbol_limit` 和 `max_items_per_run` 限制。授权但未交付的身份保持 unseen，后续正常轮询继续读取它们。
- 初始范围之外后来出现的新身份，以及已记录 IR 身份的新投影，继续按原增量规则进入；不添加永久 `from_time` 过滤。
- 原有显式 `continuous_event_cutoff` 独立生效。本轮不放宽它，也不改写入库事件时间。

实现先按既有 Inbox 合同分块验证完整历史，再分类授权集合。`AdapterPollResult` 的可选
`initial_history_sha256` 绑定全范围和授权事件指纹，纳入现有 preview SHA。首批外的授权
身份变化也会导致 catch-up 确认不匹配。Supervisor、操作员预览和 CLI preview 共用入口。
该摘要沿用已有事件 fingerprint 语义，不是 SEC 公告正文或所有可变描述字段的内容快照。

只有 Source Inbox 导入成功后，才由既有事务提交“排除身份＋本批已处理身份”的 checkpoint
及初始化 receipt。事务失败不消费初始化进度；提交 Inbox 后、提交 checkpoint 前崩溃时，
使用同一确认摘要重放，已有主事件不会重复生成。

初始化成功表示完成初始分类和当前批次，不表示所有授权历史已投递完毕。这里没有新增
冻结 payload 队列；上游移除或改写已授权未交付项后，不保证恢复原始 payload 版本。
仍位于受限查询中的授权身份可以继续跨批处理，临时遗漏后重现仍可处理。

## 修复前证据

先在基线代码运行三个真实 SEC Adapter＋Supervisor＋临时 SQLite 组合测试，3/3 失败：

- 13 条历史、每批 3 条、总授权 2 条，连续五轮实际导入 12 条。
- `from_time` 应保留 5 条，连续轮询实际导入 10 条，含被排除的旧记录。
- 初始导入事务失败本身未写入部分记录，但恢复后仍突破总授权。

修复后扩展到 SEC、RSS、Micron JSON、乱序输入、5/3 配额、遗漏恢复、新修订、崩溃重放和
摘要合同。后增加的用例属于集成覆盖，不冒称全部在基线执行过。

另一个新增 CLI 组合测试在修复入口之前失败：preview 未走完整初始化路径，缺少历史
摘要而被拒绝。统一入口后，CLI 确认 SHA 原样用于执行，四批接受数为 2、2、1、0。

## 兼容与停止边界

本补丁未新增表、列、索引、migration key、checkpoint 版本或持久化初始化 receipt 字段。
`sec_filings_checkpoint_v2`、`company_ir_checkpoint_v2` 和当前 reader 的严格校验保持不变。
新增摘要只存在于轮询/预览计算中，最终通过已有 preview SHA 持久封印。

已有 `seed_only`、房间、材料、收件箱不做迁移或重置。旧版已经完成的非默认初始化不会被
自动重新分类：旧 checkpoint 不能补出当时未记录的历史边界。需要恢复此类状态时，应先
停用，在临时副本审阅旧 receipt 和 checkpoint，再单独授权使用现有迁移路径重新预览。
不得为“修复”静默清空旧 checkpoint，已经错误导入的历史也不自动删除。

本补丁没有修复 `67fdb4ad` 不认识 Q4 sidecar/新 checkpoint 的既有回退限制，也不批准正式
原地升级或旧整库恢复。Reader 兼容与发布门属于后续 PR C；不得从本轮测试推导已兼容回退。

PR B 的命名试用配置、PR C 的发布门、PR D 的请求缓存、PR E 的真实新增和长时验收均未开展。
不合并默认分支，不更新正式安装目录，不迁移正式数据库，不启用常驻监控，不调用付费模型。
