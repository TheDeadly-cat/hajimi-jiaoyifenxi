# 双重截止策略的独立离线评审稿

状态：**运行集成候选，尚待独立评审和新的真实运行授权**。初始基线为 PR #21 的 `cebbbd11c39ebb537274172a1b00ea4382a81d43`；集成已纳入 `4852de60a73c37a7ac3a8b48c0df8448db8d93c2` 的最终发送检查。原目录、旧策略的累计两秒保护及 20260927A 证据均保持不变。本文件延续 `NEWS_REVIEW_CLOCK_POLICY_DECISION.md` 的 B 方向；离线开发不代表用户已选择新运行策略，也不授予真实调用权限。

## 要解决的问题

20260927A 先出现约 1.245 秒的系统前调，随后较小偏移累积，最终累计差超过现行 2,000 ms 保护。参考方案研究如何允许这类有限校时，同时确保授权时间只能缩短，不能因回拨、重启或重新采样延长。它不以“必须跑满一天”为成功条件。

## 明确的参考规则

激活观察由一个墙钟读数和包围该读数的两个单调读数组成。原绝对到期时间保持固定；初始单调截止为：

```text
激活时单调读数的较早边界 + (原绝对到期 - 激活时墙钟)
```

每次判断只允许将单调截止缩短为：

```text
min(已有单调截止, 当前单调读数的较早边界 + 原绝对到期 - 当前墙钟)
```

使用较早边界使采样耗时不能增加可用时长。曾被前调扣除的时间不会因后续回拨归还。到期或异常一旦发生就锁定停止，后续时间恢复也不能重开。

| 条件 | 参考结果 |
|---|---|
| 墙钟达到原绝对到期，或单调读数达到已收紧截止 | 任一先到即停止 |
| PID 或原生创建 UTC ticks 与原激活身份不一致 | 停止；不允许重启、PID 复用后续跑 |
| 单调计时回退、非整数/非法读数、采样跨度超过 50 ms | 停止，记录时钟未确认 |
| 有效观察间隔超过 30 秒，或采样区间跨越该限制、无法确认未超限 | 停止；分别记录已确认缺口或界限未确认，休眠不补跑 |
| 墙钟低于原授权开始 | 停止 |
| 墙钟比此前最高读数回退超过 2,000 ms | 停止；多次小回拨不能绕过累计回退判断 |
| 扣除单调计时区间后，一次前跳或回拨超过 2,000 ms | 停止 |
| 采样误差区间跨越正负 2,000 ms，无法确认没有超限 | 停止并标记跳变界限未确认；不能利用区间宽度放宽阈值 |
| 每次校时在上述边界内，但累计差超过 2,000 ms | 只在两种截止都未到且其他条件满足时，参考时间判断可以继续；累计差本身不重置锚点或预算 |

这些是待评审的新策略判据，与旧版本“累计两秒”具有不同语义。只有显式的新策略版本才会使用它；50 ms 采样跨度及 30 秒观察间隔亦属拟评审参数，不能冒充已批准的运行方案。

## 平台和证据假设

第一版仅建模 Windows QPC。微软文档说明 QPC 与系统时间独立，且包含待机、休眠等低功耗期间的时间；Python 在 Windows 的 `time.monotonic()` 使用 QPC。这允许在恢复后耗尽原时间预算，而不重新发放睡眠期间的时长。该语义不可直接套用到不计休眠的计时源。参考：[Windows QPC](https://learn.microsoft.com/en-us/windows/win32/sysinfo/acquiring-high-resolution-time-stamps)、[Python time](https://docs.python.org/3/library/time.html#time.monotonic)。

参考类接收注入读数，本身不证明操作系统、虚拟机计时源或外部 UTC 的正确性。实际平台能力、采样方式和进程身份必须在生产集成入口验证。实例的不可变窗口不替代宿主单次激活登记；不能靠重新构造一个对象规避持久化的启动与授权检查。

## 已完成的离线验证

新策略 16 个虚拟时钟用例，以及现行时钟 8 个回归，共 24 项通过，零网络连接。新用例覆盖：正常虚拟一天、1.245 秒前调后缓慢偏移、墙钟变慢、前调再回拨不归还时间、到期后校时不重开、大步跳变、精确阈值、多次小回拨、休眠跨窗、观察缺口、单调回退、PID 复用、慢采样、异常读数及不可变停止证据。采样区间为 29,975–30,025 ms 时，不能证明没有超过 30 秒，须停止并标记界限未确认；不会把它误称为已确认超限，也不会因此放宽限制。

上述是最初参考候选的测试范围。集成准备另补跳变区间跨界回归：`[2000,2050]` ms 和 `[-2025,-1975]` ms 原来可以继续，现拒绝并记录 `wall_clock_step_limit_unconfirmed`；整个区间都在限制内时仍可继续。这是采样不确定性的修复，未增加两秒阈值。

## 原生 Windows 采样准备

`backend/news_review_windows_clock.py` 只读取当前进程。它检查 Python 实际使用 Windows QPC，采集原生创建 UTC ticks，并用单调读数包围墙钟和身份查询。纳秒转毫秒时，前边界向下取整、后边界向上取整，避免隐藏越过 50 ms 限制的采样。无效或过慢的采样直接失败，不自动重采样来替换拟议锚点。

原生单调纳秒读数也保留在观察中，用于区分快速连续检查产生的取整区间重叠与真正的计时回退；开始后丢失该精度会停止。墙钟毫秒差额的不足一毫秒量化误差计入跳变与回拨区间，跨越限制则标记未确认，不能用取整掩盖超限。

本机一次只读核对中，原生 ticks 与 PowerShell 7 的 `Get-Process.StartTime.ToUniversalTime().Ticks` 精确一致；观察区间为 3 ms。该观察有单独文件及源文件哈希，属于当次本机能力证据，不证明外部 UTC 正确、休眠实测或连续运行。没有修改系统时间，也没有创建真实激活或观察器。当前候选已将采样器接入显式新版本的服务、来源/正文边界和最终模型准入，实际运行验收仍未开始。

1.245 秒与慢漂移用例是依据现象构造的模式，不是完整真实采样回放；旧版没有记录双读数采样区间，不能补造该证据。虚拟一天不等于实际连续一天，也没有执行系统休眠或更改系统时间。

## 集成边界与剩余验收

1. 在新策略/激活方案中显式绑定策略版本、参数、原绝对期限、原进程 pin 与原激活观察；默认旧策略和历史解释保持。
2. 只在一次成功激活中建立原窗口。禁止从旧 receipt 重新生成锚点后续跑；所有恢复入口检查原单次激活状态。
3. `NewsReviewService.approve/_identity`、来源 HTTP 准入、`check_document_send`、正文预约、模型最终发送准入统一使用同一窗口实例及停止状态。
4. 保留 `TextRequestSendGate` 与停止信号先行顺序；补足截止瞬间、暂停、主线程停止与最终 HTTP 发送竞态集成测试。当前参考类的时间判断绝不等价于请求授权。
5. 单调截止先到而墙钟未到时，报告明确停止依据，不能仍仅使用墙钟 `expired` 字段；有观察缺口时连续验收不得通过。
6. 请求的绝对截止、正文读取时限和收尾预算必须受剩余授权约束；已经准入的未知结果保留 UNKNOWN，不退预约、不重发。
7. 检查预算/内容去重、源检查点、旧读取器兼容、API 与最终报告证据；核对全部工程 CI。
8. 完成独立评审、用户对新策略的明确选择，以及绑定新候选的新授权后，才可开始真实试验。

新策略版本为 `news_event_review_dual_deadline_v1`，固定 `clock_policy` 参数及完整 `clock_activation` 纳入实际策略哈希。未绑定原生采样的模板仅能预览；启动器仅允许新激活，拒绝 `--run` 续跑。激活计划明确允许填入时间与原采样，独占激活文件先于账本审批写入。新服务对象不能重新批准或使用原实例的授权；旧数据库不能用于创建另一个双时钟窗口。

禁止的恢复请求必须在启动清理之前拒绝。只要原服务会话的双时钟绑定仍在，直接恢复、第二个服务的启动准备及控制器启动都不能暂停正在运行的策略，也不能将其在途请求改记为 UNKNOWN。确认工作线程收尾并结束原会话、移除绑定后，冷启动清理仍可保守标记旧窗口，但不能续跑或重新创建授权。

正文服务自身建立授权上下文，所以另行构造正文 runner 仍受同一截止和取消约束。来源/正文的等待、连接、分块读取预算取原超时与剩余授权的较小值。模型保留最终发送门检查；已准入模型仍按原有 240 秒请求上限和有界收尾处理，未知响应不退预约、不重发。宿主原 255 秒收尾约束保持。

到期与同时发生的异常分别保留：例如休眠后越过截止，授权已经关闭，但观察缺口仍使宿主失败退出。报告将“授权已关闭”“授权窗口观察覆盖”和“实际连续满 24 小时”分开；被正常前调收紧的窗口不冒充实际满一天。冷读取器只使用已核验日志中的原时钟证据，不建立新授权。

底层评估器的 `runtime_integrated=false` 与 `request_authorized=false` 表示单次时间判断不构成授权；运行封装另记录 `service_binding_installed`。请求仍须通过原策略、所有权、预算、内容认领及最终发送门。集成回归、准确提交的完整 CI、独立评审和事前授权分别验收；不能据此宣称长期运行问题已经通过真实验证。
