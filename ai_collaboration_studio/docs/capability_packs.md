# 领域能力包

AI 共创室的房间内核只负责成员、消息、资料、轮次、主持调度和产物。领域能力包在不改变这些核心实体的前提下，为房间增加专业能力与讨论协议。

## 当前内置包

### 结构化发言合同（群聊内核协议）

- 能力：`discussion.turn_contract_v1`。
- 所有新正式轮在创建时无条件冻结 `turn_contract_v1`；它不再是用户可取消的领域能力。`structured_turn_contract_v1` 能力包 ID 仅为历史房间和版本快照兼容保留，并由前端作为系统管理协议只读展示。
- 旧轮次与暂停恢复只读取其 round/checkpoint 已冻结的合同版本；空版本继续使用兼容旧语义，不做破坏性回填，也不能由房间当前能力反向开启。
- 每个正式成员回复由可见正文和隐藏机器合同组成。合同只能引用本轮允许的消息 ID、冻结资料 ID 或 manifest 中唯一的冻结市场快照 ID，并结构化记录回应关系、候选方案更新、风险、下一步和主观置信度；快照 revision 与 SHA 只由服务端绑定。
- 服务端依据成员当时的流程阶段、立场与能力标签执行最低字段门；合同解析失败、跨轮引用、未知字段、越权执行字段或存储/检查点版本不一致都会失败关闭，该发言不计入收敛覆盖。
- 合同与可见消息、`round_turns` 终态和下一检查点在同一事务提交；群聊与产物引用只展示去掉机器块后的正文。
- 绑定轮次生成产物时，服务端只从重新校验的正式 turn 合同确定性投影候选、风险、下一步和决策板，不从可见正文猜测，也不接受模型生成的同名区覆盖。确认前再次核对原始合同、精确身份版本、消息前缀、冻结资料和检查点成功成员集合。
- 新 v1 轮次以 canonical SHA-256 绑定成员快照、合同消息、前序正文、冻结清单、每个终态检查点和整轮 ledger；多处 v1 标记必须一致，不能仅清空轮次版本字段退回历史规则。升级前已存在但缺少封印的 v1 轮次失败关闭，纯 legacy 轮次不回填成 v1。
- 置信度只是该成员的主观判断，不能称为历史胜率、校准概率或用户最终决定。

### 结构化项目研究

- 能力：需求证据地图、候选方案矩阵、项目风险登记、条件化项目建议。
- 产物工作区：需求记录状态、负责人、验收标准和逐条证据；风险记录概率、影响、是否阻断、触发条件、缓解方案、负责人和逐条证据。
- 候选方案使用统一的价值、成本、周期、依赖、可逆性五维矩阵，并保留收益、风险、AI 条件化首选与选择理由。用户的 `support / hold / return` 及显式候选选择属于通用房间内核，不由领域能力包代替。
- 已确认需求必须具有验收标准与已核对支持证据；每条风险必须具有触发条件，已缓解/已接受风险还必须具有处置说明。
- 开放或监控中的阻断风险会阻止候选方案进入“等待用户决策”，但不会阻止用户把它确认成一份准确记录风险的会议纪要。
- 新轮会把最新项目产物转换为不含正文的缺口快照并冻结：需求/验收缺口匹配证据研究职责，阻断风险匹配反方审查职责，候选方案和矩阵缺口匹配方案整合职责。主持模型不可用时仍按同一映射安全回退。
- 讨论要求：区分用户原话、事实、假设和证据缺口；用共同维度比较至少两个真实方案；风险包含触发、影响、责任角色、缓解和验收条件；最终决定仍由用户确认。
- `project_research` 模板默认启用此包。

### 美国存储产业只读研究

- 能力：MU、SNDK、WDC、STX 的 Futu 只读行情、存储产业分析、模拟观察、纸面组合和结构化观察提案。
- 讨论要求：统一冻结数据截面、保留最强反证和失效条件、模型置信度不得冒充统计胜率。
- `us_storage_committee` 模板默认启用此包。

### 足球只读研究

- 能力包：`football_research_readonly`；端口：`core.football.match_context/v1`。
- 版本化合同封印比赛身份、开球时间、场地、赛程密度、旅行、主客场、阵容/伤停/停赛发布时间、战术、近期表现和数据截止时间，并区分官方事实、媒体信息、模型推断和赔率代理。
- v1 固定 withholding 概率状态；没有真实、任务匹配的校准能力包时不生成未来胜率，不投注、不接钱包、不下单，也不替代用户决定。
- 详细字段、材料绑定、正式轮授权和恢复语义见 `docs/readonly_domain_packs.md`。

### 通用股票只读研究

- 能力包：`stock_research_readonly`；端口：`core.market.readonly_context/v1`；房间必须保存 `stock_room_scope_v1` 显式股票池。
- 每个标的逐项预检 Futu、SEC、公司 IR、复权和公司行动，并绑定统一截止时间与精确本地材料版本；服务不访问真实外部数据源。
- 该包复用宿主证据图、治理、行动台和用户决定链，但不声明存储 candidate experiment 或 `simulation.paper_portfolio`，也不扩写 `storage_research_readonly` v1。

## 清单合同

每个包在 `backend/capability_packs.py` 的服务端白名单中声明：

- `manifest_version=capability_pack_manifest_v1`、稳定 `id`、语义化 `pack_version`、有限 `core_protocol_range` 和 canonical `manifest_sha256`；
- `name`、`category`、`description` 和界面使用的 `mode_label`；
- 一组只读派生 `capabilities`；
- 精确 `dependencies`、`domain_adapter_ids` 与 `ui_contribution_ids`；
- `discussion_protocol.title`、成员使用的 `rules` 和主持调度使用的 `director_focus`；
- 强制安全字段 `execution_capability=none`、`live_trading_allowed=false`、`can_autonomously_decide=false`、`can_replace_user_decision=false`、`arbitrary_code_loading_allowed=false` 与 `user_final_decision_required=true`。

服务端在创建、更新房间和返回能力包目录时验证安全字段。未知包，或任何声明真实执行能力的包，都会失败关闭。客户端只能选择服务端目录中的包，不能自行声明能力。

## 版本化静态插件 registry（P24 第一阶段）

`backend/plugin_registry.py` 只登记仓库内受信任的静态合同，不扫描目录、不在线安装、不动态 import，也不接受服务端下发 JavaScript、HTML、CSS 或组件路径：

- `domain_adapter_contract_v1` 冻结 adapter 版本、激活能力、读面、本地写面、外部写入禁令、Provider 预算、只读市场策略和失败关闭政策；
- `ui_contribution_contract_v1` 只能指向内核拥有的 `/v1` slot 和编译期 `component_key` allowlist，不能声明用户最终决定 slot；
- `plugin_registry_catalog_v1` 对全部 pack、adapter 和 UI contribution 生成确定性目录哈希；
- `plugin_registry_snapshot_v1` 解析系统管理包、用户选择包、依赖、adapter 和 UI contribution 的精确版本与哈希，并固定禁止动态代码加载。

房间创建时保存完整 registry snapshot。只改标题、目标或讨论设置会保留原 snapshot；能力包集合变化才由服务端重新解析。当前房间的 snapshot 损坏、同 ID manifest 漂移、未知 adapter/UI、非宿主 slot 或安全字段漂移都会失败关闭，不再从损坏能力包 JSON 静默恢复模板默认值。

新正式轮在创建事务内再次核对房间设置版本和 registry 哈希，并把完整 snapshot 与镜像哈希写入轮次；检查点由轮次绑定自动注入同一 snapshot。暂停恢复和轮次产物要求 round/checkpoint 两侧一致。升级前的旧轮次明确标记为 `legacy_unversioned`，继续按其原有能力包 ID兼容读取，但不冒充当时已经具有 P24 精确封印。

房间设置界面会显示 pack 版本、manifest 短哈希、精确 adapter、宿主 UI slot 和固定安全边界。当前阶段仍由既有内核组件执行这些 contribution；把 ArtifactDialog 的所有显示门从“当前房间能力”迁移到“产物所属轮次 snapshot”是下一纵向切面，不在本阶段加载第三方前端代码。

## 能力包与领域适配器

能力包是房间持久化的声明式合同，领域适配器是可选的运行时实现。通用聊天、材料、轮次、主持和产物内核不直接依赖存储市场服务，也不在通用提示中包含富途、指定股票、交易研究或投委会语义。

- `DomainAdapterRegistry` 以适配器的 `activation_capabilities` 与房间冻结能力的交集决定是否激活。没有能力交集的适配器不会因注册存在而自动进入房间。
- 需要专业实现的能力由服务端维护强制映射。房间声明了这类能力但对应适配器未知或缺失时，Registry 失败关闭；不会跳过专业数据门，也不会生成替代行情或退回较弱的通用流程。
- 每个适配器注册和解析时都必须通过接口与安全合同验证，并固定声明 `execution_capability=none`、`live_trading_allowed=false`。任何可执行、允许实盘或接口不完整的实现都会被拒绝。
- 行情适配器必须额外声明 `provides_market_context=true`，并仍由能力交集激活。同一房间最多允许一个行情适配器；命中多个时失败关闭，避免一轮混用不同数据截面。
- 当前存储研究适配器负责 Futu 只读行情预检与冻结、领域提示上下文和时间线、观察提案机器块及其持久化规则，以及会议产物中的冻结行情证据类型。移除存储能力包后，这些语义不会进入之后的新轮或通用房间。

## 运行时语义

- 模板只提供领域包初始选择；创建后用户可独立增删领域能力包。核心 `turn_contract_v1` 不属于这一可选集合。
- 核心协议和领域包协议会进入隐藏主持调度及成员系统指令，外部资料不能修改这些协议。
- 新轮开始时冻结能力包 ID、派生能力和适用的项目工作区缺口；运行中或暂停后修改房间或项目产物，只影响下一轮。绑定轮次生成会议产物时也读取该轮冻结能力，而不是房间此刻的最新设置。
- 取消领域能力包不会删除历史消息、资料、观察或模拟组合，只会关闭之后轮次的对应专业入口；不能借此关闭核心发言合同。
- 能力包不得创建账户、解锁交易、委托、投注、支付或其他资金执行能力。
- SQLite 内的 SHA-256 只提供本地一致性与防误改线索，不是抵抗数据库管理员的 HMAC、数字签名或外部公证。

## 增加新领域

新增包应先定义可审计的研究能力和讨论协议，再决定是否需要独立只读领域适配器或界面。若需要适配器，应声明互不含糊的激活能力、是否提供行情上下文，并把必需能力加入服务端强制映射；不得在通用 orchestrator 或产物服务中增加领域名称分支。至少需要覆盖：能力包与适配器安全验证、未知/缺失适配器失败关闭、多个行情适配器冲突、模板默认值、成员和主持提示、前端能力标签、创建/更新/暂停恢复测试，以及一个非密钥的隔离浏览器验收流程。
