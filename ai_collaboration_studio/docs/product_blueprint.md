# AI 共创室：产品大纲 v0.1

## 1. 产品定义

AI 共创室不是“把多个聊天机器人摆在一起”，而是一个可编排、可追踪、可积累的协作空间：

> 用户创建一个房间，定义目标和规则，为 AI 成员赋予身份；用户与成员在群聊中讨论，成员能够阅读上下文、回应彼此、提出反证、分工研究，并把过程沉淀为结论、待办和可继续编辑的产物。

股票研究、体育研究、项目可行性、方案撰写只是场景模板，不是产品边界。

## 2. 四个核心原则

1. **身份高于模型**：用户看到的是“战略主持人、反方审查员、事实研究员”，模型只是身份背后的执行器。
2. **对话高于报告**：观点必须出现在连续群聊里，后发言者需要读取并回应前序观点。
3. **证据高于气氛**：重要结论必须能追溯到发言、材料或用户输入；不把一致意见伪装成事实。
4. **产物高于热闹**：每个房间最终要形成结论、分歧、待办和可导出的文档，而不是无限闲聊。

## 3. 核心对象

### 房间 Room

- 标题、目标、场景模板、房间规则。
- 成员、共享材料、消息、讨论轮次、结论与待办。
- 可长期存在，不因一次模型请求结束。

### 成员 Member

- 显示名：例如“反方审查员”。
- 身份说明：它是谁、负责什么、不负责什么。
- 发言风格：简洁、严谨、创意、挑错等。
- 模型适配器和模型名。
- 是否参与当前轮次、发言顺序和权限。
- 成员身份使用单调版本和 `expected_version` 防止并发覆盖；“移出房间”采用可恢复归档，保留消息、结构化点名、轮次和身份历史，恢复后继续由用户编辑职责与边界。活动和归档身份历史均可只读列出、精确读取并进行双版本差异对比，损坏快照不会回退到当前身份。

### 讨论轮次 Round

- 本轮目标。
- 参与成员和发言顺序。
- 前序记录、暂停/继续/停止状态。
- 每位成员的开始、完成、失败和耗时事件。
- 主持人每次点名或建议结束都按服务端正常写入路径追加审计记录，包括顺序、理由、来源、阶段、关注点和冻结主持上下文；新记录以 `decision_sha256` 封印，刷新或恢复后仍可回看。旧轮不补造封印，轨迹会诚实显示 `partial`。

### 消息 Message

- 用户消息、AI 消息、系统事件。
- 发言者、回复对象、轮次、时间和模型来源。
- 后续支持引用、编辑分支和重新生成。

### 共享材料 Context

- 粘贴文本、文件、链接、结构化数据和工具结果。
- 每份材料保留来源、更新时间和可见范围。

### 产物 Artifact

- 会议纪要、通用多方案决策板、研究简报、决策记录、任务清单；结构化项目房间还把需求证据地图、风险登记和价值/成本/周期/依赖/可逆性方案矩阵保存在同一版本化产物中。决策板保留所有候选、AI 条件化首选、首选理由和反证，不把多数票或模型语气冒充用户决定。
- 由用户确认记录与证据后进入正式版本；AI 草稿不得自动覆盖用户版本。
- 产物确认不等于用户最终支持 AI 首选。用户可对已确认的精确版本显式选择任一有效候选，例如 AI 推荐 A、用户支持 B；也可保留或退回并填写理由。版本变化后旧决定过期，但仍保留在不可变历史中。
- 已确认精确版本中的待办可由用户逐项采纳到独立行动台；负责人、期限、状态和备注随后以追加事件推进，不反向改写产物、最终决定或 AI 讨论记录。工作区级行动总览只读汇总同一数据库快照内通过完整性核验的房间，支持本地筛选和精确返回来源房间；新版待办不会静默继承旧版进度，只能由用户确认独立的旧版→新版延续关系。

## 4. 主要工作流

1. 新建房间并填写本轮目标。
2. 从独立于模型路由的身份模板目录选择成员，或自行定义身份；套用模板只填入身份、职责、边界、阶段与能力标签，不改变 Provider、模型、启用状态和历史版本。
3. 添加共享材料。
4. 用户在群聊中发言，或点击“开始一轮”。
5. 系统只读生成启动计划，冻结角色、主持路由和 Provider 调用次数投影；用户明确确认 1–28 次全局上限后，服务端重新构建并核对计划。计划中的 `recommended_director_calls` 同时冻结为 `round_director` 硬子预算，只能收紧而不能扩大用户授权。存储领域先通过只读行情门，再创建本轮唯一调用账本。
6. 编排器在冻结的房间流程政策内，由主持人动态选择下一位成员；每次选择或建议结束都先追加带 `decision_sha256` 的审计记录。规则可证明唯一、主持子预算耗尽、全局名额需保留给正式发言或主持调用失败时，系统都不伪造 AI 选择，而使用安全确定性回退并记录来源。每位成员读取房间目标、同轮冻结材料、证据截面和前序发言。
7. 每个新正式轮都由内核冻结 `turn_contract_v1`：成员必须明确赞同、补充或质疑谁，并在不可见合同中提交可校验的消息、资料或本轮唯一冻结市场快照引用，以及风险、候选更新和下一步；快照 revision 与 SHA 由服务端绑定，无效合同不计入收敛。旧轮和暂停恢复只服从自身冻结版本，不事后回填。
8. 用户随时插话或请求暂停；暂停由服务端持久化，并在当前成员发言后的安全检查点确认，不把前端断流误当成后端已停止。用户也可调整身份或改变顺序，冲突操作在暂停确认前保持锁定。
9. 系统只从目标轮次冻结的消息、成员身份版本和资料确切版本中整理结论、分歧和待办。合同轮的候选、风险、下一步与决策板由正式 turn 合同确定性投影，不允许整理模型覆盖；生成与确认都重新校验原始合同、精确身份、引用前缀、资料清单、成功成员集合和整轮 ledger。v1 的 round、checkpoint、message 与 ledger 标记必须一致，不能降级为 legacy 绕过门禁。确认时再次要求关联轮次为 `COMPLETED`，并按冻结政策重算成功成员、阶段与职责覆盖；暂停、部分、取消或覆盖不完整轮次只能保留草稿。轮后内容不能倒灌到旧轮产物。
10. 产物确认后，用户再对精确版本选择支持、保留或退回并填写理由。该决定不授权下单、账户、投注、支付或其他资金动作；产物修订后旧决定自动过期。

## 5. 场景模板

模板声明默认分类、成员和能力包，但三者都不是同一个概念。用户创建房间时可以修改“交易研究 / 美股 / 自定义”这类分类路径，并独立选择服务端白名单中的领域能力包；模板只负责给出默认值。所有房间固定拥有群聊、共享资料和会议产物三项通用能力。“结构化项目研究”包追加带状态、验收标准和证据的需求地图，带概率、影响、触发条件和处置方案的风险登记，以及价值/成本/周期/依赖/可逆性候选方案矩阵；“美国存储产业只读研究”包追加 Futu 只读行情、存储产业分析、模拟观察、模拟组合风控与结构化观察提案。两者都明确没有真实执行能力。

创建后用户仍可修改房间名称、长期目标、分类、调度模式和能力包。已运行或暂停轮次保留创建时冻结的能力合同，房间的新设置从下一新轮生效；成员身份修改仍按成员身份版本从该成员下一次发言生效。

- **开放共创**：主持人、创意提出者、反方审查员、落地设计师。
- **项目研究**：研究负责人、事实研究员、商业审查员、方案架构师。
- **方案撰写**：结构编辑、内容作者、读者代表、质量审校。
- **体育研究**：数据研究员、战术观察员、风险审查员、信息核验员。只做研究，不代替用户投注或执行资金动作。
- **市场研究**：趋势研究员、基本面研究员、反方审查员、风险记录员。只做研究，不执行交易。
- **美国存储产业投资委员会**：正式目标为主持人、存储周期、硬盘产业、基本面、技术与资金、新闻与情绪、多头、空头、数据质量官、模拟交易员、风险经理和投委会决策经理 12 个独立角色。数据质量官负责统一截止时间、冻结版本和防未来数据泄漏；该模板只研究 `MU/SNDK/WDC/STX`，不执行交易。

## 6. 技术架构

```text
React Client
  -> Room API / NDJSON Round Stream
  -> Room Routing & Provider Preflight
  -> Discussion Orchestrator
       -> Identity Prompt Builder
       -> Frozen Context / Evidence Builder
       -> Dynamic Moderator + Safe Fallback
       -> Service-path Append-only Director Decision Trace + Seals
       -> Provider Call Ledger + Kind Budgets + UUID4 Operation Binding
       -> Provider Registry
            -> OpenAI / DeepSeek / Ark-Doubao / GLM Adapters
  -> Capability Packs
       -> Trading Research Pack
            -> Futu Read-only Market Adapter
            -> Evidence / Observation / Paper Portfolio Services
  -> SQLite Store
       -> rooms / members / identity_versions / messages / rounds
       -> provider_execution_runs / provider_call_attempts
       -> director_attempts / director_decisions / round_trace_anchors
       -> artifact_user_decisions
       -> materials / checkpoints / artifacts / observations
```

关键边界：

- 编排器只依赖统一 `Provider` 接口，不知道厂商 API 细节。
- 身份提示词属于成员，领域模板属于房间，两者不能写死在模型适配器中。
- 房间持久化 `capability_pack_ids`，能力由所选能力包派生并随房间 API 返回；模板只提供默认包。能力包还声明受信任的成员讨论规则和主持调度重点，使专业方法能够插入通用编排，而不是散落成模板名称判断。当前结构化项目研究包与美国存储产业只读研究包共享同一套房间内核。
- 未注册的能力包由服务端拒绝；客户端不能自行声明任意能力，更不能通过包名打开下单、账户或资金权限。
- 前端只接收 provider、model、状态等安全元数据，永远不接收密钥。
- 新正式轮的每个实际 Provider attempt 都在请求上游前获得 UUID4 `operation_id`，并精确绑定到规范预检路由、主持尝试、正式 turn、轮内插话请求或纪要 generation key；全局调用上限和 `round_director` 类型子预算都按预留计数，失败、无效、取消或遗留尝试不退款。
- 新正式轮在暂停或终态安全边界追加非敏感 `round_trace_anchor_v1` 并推进链头；旧轮不回填 operation、主持决定封印或 anchor，继续标记 `partial`。决定封印、operation 绑定和锚链都与业务数据同存 SQLite，只是本地一致性与局部防篡改证据，不是签名、外部时间戳或能抵御恶意数据库管理员重写的公证。
- Provider 路由属于通用内核；富途、存储股白名单、财报和模拟观察属于交易研究能力包，不能污染通用房间与群聊编排核心。
- 交易研究能力包只生成事实、反证、模拟方案和观察条件，不含账户、解锁交易、委托或资金动作。
- 高风险外部动作必须由未来独立工具权限层处理；第一阶段完全不提供执行工具。

## 7. 路线图

### Phase 1：能讨论（第一层已完成）

- 房间、成员身份、连续群聊、动态主持与安全回退、SQLite、多 Provider 适配器。
- 主持人的每次点名与建议结束均持久化为可刷新恢复的不可变审计轨迹。
- 用户可随时插话并开始下一轮。

### Phase 2：能共创（第一层已完成）

- 共享文件和链接、引用证据、身份模板、动态发言顺序。
- 主持人根据分歧决定追问谁，而不只是固定轮询。

### Phase 3：能产出（第一层已完成）

- 结论/分歧/待办自动整理。
- 文档工作区、版本对比、产物确认、与精确版本绑定的用户支持/保留/退回决定，以及导出。

### Phase 4：能扩展（进行中）

- 插件化模型与工具、语音房间、团队协作、权限与成本预算。
- 领域包只提供模板、资料连接器和评价标准，不污染核心聊天架构。

### 当前验收目标

1. 房间级 provider / model 路由，不改变可编辑 AI 身份。
2. 新轮先只读生成并复核调用计划；当前存储委员会的核心成功路径是 2 次预检与 12 次最低成员发言，另建议 6 次真正歧义的动态主持和 1 次可选纪要，共建议授权 21 次。确认后 6 次主持额度冻结为 `round_director` 硬子预算，用户确认的全局硬上限独立且优先强制；所有正式轮调用复用同一持久账本，失败、无效、取消和遗留尝试均不退款，预检失败时不产生半轮讨论。
3. 当前使用已实测通过的 DeepSeek 与豆包完成非 OpenAI 模型链路验收；GLM 修复授权前保持不可用告警。
4. 启动本机 Futu OpenD，配置合规但不回显的 SEC User-Agent，取得四只白名单股票的同批次 `ready` 快照和可用官方申报索引。
5. 由新正式轮的核心协议完成一次“Futu 统一只读快照 → 12/12 角色均以合格 `turn_contract_v1` 动态讨论，且每位非首位成功 AI 都以可审计合同边回应此前正式 AI → 可恢复主持审计轨迹 → 数据质量官防未来数据核验 → 冻结证据清单 → 绑定 `round_id` 的纪要/分歧/待办 → 服务端自动钉住并由用户核验该轮冻结市场快照 → 产物确认 → AI 推荐 A、用户可显式支持 B”的真实验收。离线临时库已由明确的 fixture 用户走通代码链；下一步仍是获准的真实 Provider 轮和真人复核。产物使用稳定条目 ID，开放分歧、空纪要、无效发言合同、回复投影漂移或未核验的精确市场快照都不能确认；最终决定理由必填、选择必须绑定精确候选、版本变化后旧决定过期，且只进入研究与模拟，不提供任何执行能力。OpenAI 保持禁用，不预检、不调用、不回退。
6. 对精确版本的纸面组合提供四股共同 QFQ 日线历史滚动回放：固定初始名义、下一交易日收盘模拟入场、入退场成本、完整输入冻结和至少 20 个非重叠测试窗口的数据门。结果必须标记为当前计划的追溯回放，不能声称策略样本外验证或未来胜率。

## 8. 第一阶段验收标准

- 新建房间后无需刷新即可进入。
- 至少三个不同身份能按顺序发言。
- 后发言者能点名前序成员并回应其观点。
- 用户消息和 AI 消息在同一时间线中显示。
- 刷新页面后房间、身份、消息和主持人点名/结束轨迹仍存在。
- 产物确认不会自动生成用户最终支持；支持必须显式记录用户所选候选且允许不同于 AI 首选，保留或退回不记录候选；三者只绑定已确认的精确版本，理由必填，修订后旧决定过期。
- 模型失败只影响当前成员，不中断整个房间。
- 密钥不进入前端、日志、SQLite 或版本库。
