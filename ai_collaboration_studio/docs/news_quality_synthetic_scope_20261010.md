# 固定合成基准的独立任务范围

实际豆包基准在 36 项有效响应中，出现 32 个重要性与 35 个审核状态偏差。用户采纳后的正式均分为 7.25，仍未通过每项至少 9 分且无严重错误的门槛。多数实际理由把“合成、附件未读”一并用于否定材料内的重要性与审核完成状态。

本修订仅在 PR #23 的冻结质量候选 `4d2d6226f6c6e8590e315b681d89e1152150c438` 之外建立新的质量候选。它澄清固定合成案例的任务范围，未修改自然新闻提示、原始案例、已签核参考、原输出、评分程序或既有分数。实际原因并未唯一证明，新提示的模型效果尚未测试。

## 具体行为

准备器不再把固定合成材料描述为正在审核的真实官方公告，而是明确为已读合成案例。原有不可信输入、段落引文、禁止外部补写和交易建议、局限、附件缺失与输出格式约束保留。

附加说明要求只评价材料内内容，不能把合成案例当作实际发行人事件；合成标记和通用范围警告继续列为局限。它们本身不能替代对重要性或 assessment 的判断。reviewed 仅指输入支持的主要内容已审核，不表示真实性或附件完整已确认；主要结论确需未读内容时仍必须 material_insufficient。重要性应独立判断内容中事项值得关注的程度，不照抄确定性路由。

这份说明只供固定合成基准使用。自然事件仍使用 `news_review_contracts.INSTRUCTIONS`，不能因本修订降低真实消息的证据要求。

## 新身份与旧批准

准备器使用独立 `QUALITY_STRATEGY_SHA`，由基准范围、完整新提示与原自然审核策略摘要共同形成。当前基准策略 SHA-256 为：

`f6927b715c9261353bcf373da263ca1218750f8d3f2b277a25827c761d99aac3`

原策略 `edff07be89e42a8c8dd0f3deb3b099af9bb481fb90cd25cca4bb11f60129c7e5` 保持自然审核用途。完整请求、请求 ID、准备结果及未来执行方案随新提示重新绑定，不能复用旧实际请求回执、评分、批准摘要或过期窗口。

已签核参考的正文、案例、范围与摘要匹配时继续复用，不要求重新签核全部参考。未来新实际输出须另行人工评分，不能继承用户对旧 36 项实际输出的采纳。

## 离线验证

7 个质量子系统模块合计 96 项回归通过，使用既有隔离测试入口、临时 runtime／数据库，网络审计的连接、阻断及模拟连接计数均为零。完整远端 CI 需绑定实际新提交单独核对，本地结果不代替远端 CI。

逐项对比真实旧方案与新请求投影：36 项输入和正文版本保持一致，除 instructions 外模型请求字段完全一致；36 个请求身份全部改变。两个缺失／截断案例继续不发送，重复、修订及恢复动作保持。参考答案仍不进入模型请求，原评分门槛与执行器策略保持。

每个请求增加 400 字节，最长 3,919 字节，小于原 4,096 字节上限。保守预约从 2.314926 元变为 2.401326 元，仍在原 2.50 元上限内；总预约 198,621 tokens，小于原 207,072 上限。仍为 36 次请求、输出最多 1,400 tokens、原固定豆包模型及 Responses 端点，不增加预算、调用数、重试或来源。估算不等于供应商账单。

投影对比最初在禁用 site 的 Python 环境下缺少 tzdata，未产生准备结果；使用既有已安装依赖后完成。未改依赖、CI 或测试运行器。另一次原字节对比发现新旧检出文件有 CRLF／LF 差异；读回复核内容与 Git 差异一致，未把行尾差异说成逐字节相同，也未批量改写未变文件。
