## 问题与改动

- 希捷的已保存窗口显示，两次从每小时恢复到每半小时后，第二次半小时检查又返回 429。原实现仅凭三次成功就降低退避级别。现在每次 429 都持久保存 24 小时的恢复等待，至少三次到期成功且等待结束后才降一级；若仍有压力，下次降级再等 24 小时。成功仍按原节奏采集，不停止等待期间的到期检查。这个时长是保守的客户端策略，不是希捷承诺的安全频率；可能延长新公告发现延迟。
- 保留 Retry-After、更长既有期限、手动刷新约束和独立的 403 压力。旧数据库新增一列；已有压力从迁移时起保守等待，重复启动不会续期。不会改写旧检查、旧消息、已读状态或缓存标识。写入失败后的暂存约束也携带恢复期限。
- BLS 地址仍是其[官方 RSS 帮助](https://www.bls.gov/help/hlp_rss.htm)公布的地址。[BLS 自动采集条款](https://www.bls.gov/bls/blsterms.htm)说明可能阻止没有可联系信息的机器人。诚实的产品 User-Agent 增加公开项目联系页；保持原 URL、代理约束和缓存条件，不伪装浏览器、不自动切换出口、不增加请求重试。缺少联系信息是已证实的请求标识缺口，但没有证据证明它就是本次 403 的原因，**BLS 403 尚未实测解除**。
- 将超时、DNS、TLS、连接、跳转拒绝、内容过大、无效 XML 与不允许的 XML 结构分开。保存固定错误枚举、失败阶段和真实已收到的 HTTP 状态；不保存异常原文、代理地址、原始响应头或错误响应正文。收到 200 后读取超时仍是失败，收到 302 后拒绝跳转仍记录真实 302。

## 应用到离线候选

1. 保留原安装和运行数据，准备单独的源码副本；不要在正在运行的安装目录应用补丁。
2. 将 `manifest.json` 中所有非 null 的 `before_sha256` 与目标文件逐字节核对，新文件应不存在。任一不匹配就停止，不强行合并。
3. 在该副本根目录使用 `git -c core.autocrlf=false -c core.whitespace=cr-at-eol apply <repair.patch绝对路径>`，或仅用 `overlay/` 的七个文件替换对应路径。核对全部 `after_sha256`。保留原文件行尾；`.gitattributes` 禁止 Git 改写本包文件字节。默认 Git 自动换行会改变部分文件的字节，不能省略这里的配置；初次换行不匹配回执已在本地保留，显式关闭后七份文件全部精确匹配。
4. 如需复核，可用标准库 Python 执行 `run_focused.py <已应用候选根目录>`；它先核对目标哈希，只运行本包声明的 20 个针对性检查并阻断网络。
